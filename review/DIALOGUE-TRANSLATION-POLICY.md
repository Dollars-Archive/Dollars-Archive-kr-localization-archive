# 대사 번역 공통 원칙과 화면 배치 기준

실제 대사 번역 또는 언어 검수 전에 이 문서와 게임별 기준 자료를 읽습니다. 공통 원칙은 현재 검수 단계의 범위를 넓히는 지시가 아닙니다. 각 단계는 해당 단계 지시문만 사용하며, 다른 단계 지시문을 함께 읽거나 그 단계의 작업까지 수행하지 않습니다.

**최초 한글 출력 때 [출력·진행 안전성 사전검증](../workflow/EARLY-TEXT-RUNTIME-GATE.md)을 수행하고, 그 결과인 게임별 출력/진행 규격을 번역 시작 전에 확인합니다. 한글 표시 성공만으로 다음 대사·다음 장면 진행 성공을 대신하지 않습니다.** 아래의 줄바꿈·자연화 지시는 이 규격에서 허용된 변환에만 적용됩니다.

## 1. 의미·문맥·캐릭터 보존

**원문에 충실하다는 것은 직역하라는 뜻이 아니며, 자연스럽게 번역한다는 것은 마음대로 내용을 바꾸라는 뜻이 아닙니다.**

- 한 행만 떼어 보지 말고 앞뒤 대사, 장면, 화자와 청자를 확인합니다. 문맥이 부족하면 불확실한 부분을 표시합니다.
- 일본어 어순과 생략을 기계적으로 복제하지 않습니다. 다만 생략된 주어·목적어·관계를 근거 없이 확정하거나 원문에 없는 설명을 추가하지 않습니다.
- 의도된 모호함, 중의성, 복선과 정보 공개 순서를 보존합니다. 뒤에서 알게 되는 정체나 사실을 앞선 대사에 미리 풀어쓰지 않습니다.
- 화자 → 청자 방향의 존대·반말·호칭은 해당 게임의 관계도와 실제 문맥을 따릅니다. 상대·장면·감정·관계 변화에 따른 예외는 근거와 적용 범위를 기록합니다.
- 캐릭터별 어휘, 문장 길이, 리듬과 말버릇을 살리되 모든 인물을 같은 말투로 만들거나 말버릇을 모든 문장에 기계적으로 붙이지 않습니다.
- 욕설, 비꼼, 농담, 성적 뉘앙스, 언어유희의 기능과 강도를 임의로 세게 하거나 약하게 하지 않습니다. 대응이 어려우면 후보와 손실을 설명합니다.
- 고유명사, 이름, 칭호, 애칭, 기술·아이템명은 승인된 용어집을 따릅니다. 새로운 표기는 후보로 기록하고 근거 없이 기존 확정값을 뒤집지 않습니다.
- 감탄사, 침묵, 말 끊김, 문장부호는 감정과 호흡을 보존합니다. 화면 배치용 줄바꿈과 연출용 대기·페이지 전환은 구분합니다.
- 음성이 실제로 제공되고 확인 가능할 때만 보이스의 감정·호흡과 대사를 대조합니다. 듣지 않은 음성을 확인했다고 보고하지 않습니다.
- 선택지는 선택 후 행동과 의미가 맞는지 확인합니다. UI, 내레이션과 인물 대사는 각각의 기능에 맞게 번역합니다.
- 원문 오류나 말실수가 의도인지 불분명하면 임의 교정하지 않고 근거와 후보를 남깁니다.
- 길이를 줄여야 하더라도 핵심 의미를 삭제하거나 문장 뒷부분을 잘라내지 않습니다. 제약을 만족하기 어려우면 수정 후보 또는 기술 검토 대상으로 남깁니다.

기준 우선순위는 실제 플레이 중 사용자가 직접 확정한 수정 → 게임의 실제 문맥과 대사 → 등록된 용어집·관계도·말투 규칙 → AI 제안입니다. 사용자 확정 번역과 줄바꿈은 자동 재작성하지 않습니다. 새로운 기술 제약과 충돌하면 근거를 보고하고 재승인을 받습니다.

## 2. `[n]`의 의미와 변경 허용 범위

**해당 게임에서 화면 배치용 명령으로 확인되고, 수행하려는 변경 동작의 표시·음성·연출·다음 대사·다음 장면 진행 안전성이 검증된 `[n]`만 한국어 번역문에서 변경합니다.** 다른 게임에도 같은 의미라고 추정하지 않습니다.

`유지 / 삭제 / 이동 / 추가 / 개수 변경`은 게임별 출력/진행 규격에서 각각 `PASS / FAIL / UNTESTED`로 관리합니다. 삭제 성공을 이동·추가 허가로, 자동 줄바꿈 성공을 장면 진행 성공으로 확대하지 않습니다. 실제 사용할 조합도 대표 샘플로 확인합니다.

**변경 뒤 진행이 멈춘 작품은 해당 동작을 금지하고 마지막 정상 배치의 검증된 불변조건을 보존합니다. 미검증도 변경 허가가 아닙니다.** 2차·3차라는 이유로 금지된 `[n]` 재배치를 강행하지 않습니다. 불변조건 안에서 한국어를 다듬기 어렵다면 기술 검토/HOLD로 남깁니다.

원문 필드와 그 안의 `[n]` 위치는 보존합니다. 예외는 번역 필드의 검증된 배치 명령에만 적용합니다. 페이지 전환, 대기, 음성, 연출, 변수, 분기 명령, 미확인 태그는 보호 대상이며 예외에 포함하지 않습니다. 보호 명령이 기준으로 삼는 대사 구간을 넘겨 문장이나 명령을 이동하지 않습니다.

`[n]`이라는 문자 표기, CSV 파일의 행 구분, 셀 안의 실제 개행을 같은 것으로 취급하지 않습니다. 파서와 빌더가 확인한 토큰만 다루며 일괄 문자열 치환으로 모든 개행을 지우지 않습니다.

다음은 의미와 배치 분리의 예시이지 실제 가로폭·진행 검사를 통과한 결과가 아닙니다. 해당 동작이 허용된 게임에서만 후보로 사용할 수 있습니다.

```text
기존 배치:
그래,[n]이제부터 시작이야!

한국어 기준 후보:
그래, 이제부터 시작이야!
```

```text
어색한 배치:
그래, 이제부터 시작이야 앞으로[n]나아가야 해. 절대 포기하지 마!

한국어 호흡 기준 후보:
그래, 이제부터 시작이야 앞으로 나아가야 해.[n]절대 포기하지 마!
```

문장부호, 조사·어절, 호흡을 고려하되 실제 픽셀 폭·최대 줄 수와 게임별 진행 규격을 통과한 위치만 최종 확정합니다. 자동 줄바꿈과 `[n]` 삭제 후 진행까지 검증된 게임은 명시적 `[n]`이 불필요할 수 있으므로 원문 개수와 위치를 무조건 맞추지 않습니다. 보존이 필요한 작품에는 이 예외를 적용하지 않습니다.

### 반각·전각·공백·문장부호 보호

반각/전각 변환을 단순 미관 정리로 처리하지 않습니다. 실제 게임에 등장하는 영문·숫자·공백·문장부호·가나를 종류별로 시험하고, 코드 포인트·게임 인코딩 바이트·레코드/명령 변화와 진행 결과를 분리해 확인합니다.

안전성이 미검증이거나 실패한 구간에는 전각↔반각 일괄 변환, NFKC/NFKD 등 호환 정규화, 자동 공백 trim·축약, 문장부호 교정을 하지 않습니다. 다른 자동 정규화도 허용 범위를 먼저 검증합니다. 원문의 모든 일본어 본문을 고정하라는 뜻이 아니라, 번역 가능한 본문과 폭/바이트/명령에 민감한 보호 부분을 나누라는 뜻입니다.

반각/전각 변경 후 진행 이상이라는 사용자 보고는 재검증 대상으로 우선 기록하되, 그 원인이 문자 폭인지 인코딩·길이·폰트 매핑·명령 파싱인지 조사 전에 확정하지 않습니다.

## 3. 검수 단계별 책임

| 단계 | 담당 | 화면 배치 범위 |
|---|---|---|
| 1차, 1,000행 | 기초 규칙 생성·확인, 구조, 관계, 존대, 호칭, 용어 판정 | `[n]` 재배치와 전 행 픽셀 정밀 검사는 맡기지 않음. 이미 검증된 길이·명령·반각/전각 보존 규칙만 활용 |
| 2차, 1,000행 | 자연스러운 한국어 문장과 캐릭터 말투 완성 | 허용 구간 안에서 번역. 안전성이 확인된 동작에만 `[n]` 예외 적용. 최종 배치는 확정하지 않음 |
| 3차, 500행 정밀검수 | 의미·뉘앙스 최종 수정 후 화면 배치 확정 | 허용된 `[n]` 변환만 적용하고 픽셀 폭·최대 줄 수·보호 조건·RSC 별도 검사 |

각 차수는 전체 대사집을 다시 훑는 별도 패스입니다. 마지막 잔여 블록을 제외하면 사용자 관리 단위는 1,000 / 1,000 / 500행을 유지합니다. 내부 검토를 작은 장면 묶음으로 나누는 것은 가능합니다.

2차에서 안전성이 확인된 배치용 `[n]`은 허가된 동작에 한해 번역 초안에서 제거하거나 임시 위치로 옮길 수 있습니다. 안전성이 미확인 또는 실패한 명령은 보존하고 의미 수정 후보를 비고에 남깁니다. 반각/전각·공백 보존 규칙도 유지합니다. 2차 결과를 바로 최종 패치로 반입하지 않습니다. 이미 알려진 길이 제한도 무시하지 말고 명백한 초과는 표시합니다.

3차에서는 언어 수정이 끝난 뒤 배치를 계산합니다. 배치를 확정한 뒤 문장을 다시 고치면 변경 행의 배치와 제한 검사를 다시 수행합니다. 보존이 필요한 `[n]`과 문자 폭 조건은 3차에서도 자동 변경하지 않습니다.

## 4. 게임별 출력 규칙의 선행 기술 검증

이 절은 최초 한글 출력 때 수행하는 별도 엔지니어링 작업입니다. [최초 출력·진행 안전성 사전검증](../workflow/EARLY-TEXT-RUNTIME-GATE.md)에 따라 **대량 번역 전에 안전한 한글 출력·진행 경로와 착수 판정**을 확보합니다. 번역 검수자가 매 묶음마다 게임 구조를 재분석하는 작업이 아닙니다. 해당 프로젝트가 이를 '6단계'라고 부르면 그 기술 단계의 최우선 합격 조건으로 기록하되, 모든 작품의 단계 번호를 6으로 강제하지 않습니다.

프로젝트별로 다음을 실제 파일·렌더링·런타임 근거와 함께 확정합니다.

| 확인 항목 | 남길 근거 |
|---|---|
| 대사창의 가로 픽셀 한계 | 내부 표시 영역, 여백, 화자 표시·아이콘, 글자 전진 폭·자간·배율·윤곽선과 실제 잘림 경계 |
| 조건부 최대 글자 수 | 고정폭 셀 수 또는 한글·영문·숫자·혼합 문구별 안전한 글자 수와 폰트·폭 조건. 정확한 상한 미확정 시 안전범위로 표시 |
| 최대 표시 줄 수 | 대사창 종류별 최대 줄 수, 줄 높이와 베이스라인 |
| 자동 줄바꿈 | `[n]` 유무에 따른 실제 표시 차이와 경계 사례 |
| `[n]` 안전성 | 유지·삭제·이동·추가·개수 변경 각각의 대사/장면 진행, 음성, 연출 및 다른 제어 명령 동작 비교 |
| 반각·전각과 공백 | 문자 종류별 코드 포인트·인코딩 바이트·진행 결과, 보호 구간·허용 변환·정규화 금지 조건 |
| 폭·줄 수 초과 증상 | 잘림, 겹침, 멈춤, 다음 대사·장면 진행 이상과 재현 조건 |
| RSC의 실제 의미 | 파일 크기·레코드 길이·인코딩 바이트·렌더 버퍼 등 무엇을 제한하는지, 측정 단위·한계·실제 증상. 미확인은 미확인으로 기록 |
| 긴 한글 대사의 안정성 | 긴 단어, 숫자·영문 혼합, 복잡한 받침, 변수 치환 결과, 여러 줄의 표시와 다음 대사·다음 장면 진행 |

글자 수로 가로폭을 대신하지 않습니다. Pretendard Bold를 승인한 작품은 **그 작품의 Pretendard Bold 실제 적용 크기와 렌더링 조건**으로 측정합니다. 다른 작품은 사용자가 승인한 폰트를 사용하며 Pretendard Bold를 공통 기본값으로 강제하지 않습니다.

화면 픽셀 제한, 최대 줄 수와 RSC 제한은 서로 별개입니다. 화면 안에 들어간다고 파일·레코드·버퍼 제한도 통과했다고 판단하지 않습니다. 실제 빌더의 인코딩, 명령 바이트와 종료 처리 등 검증된 계산 기준을 사용합니다.

기술 결과는 게임별 `layout_profile` 또는 기존 동등 자료로 보존합니다. 게임·버전, 폰트 식별값과 크기, 대사창별 가로폭·최대 줄 수·조건부 글자 수, 자동 줄바꿈, 토큰 동작별 허가와 구간, 반각/전각·공백 보존 규칙, 보호 토큰, RSC 정의와 한계, 표시·진행 결과, 검증 상태·증거·버전을 기록합니다. 알 수 없는 값을 임의의 숫자나 기본값으로 채우지 않습니다.

안전한 진행 경로가 미확정이면 조사용 소량 언어 작업과 기준자료 보강은 가능하지만 해당 범위의 대량 번역·최종 적용은 보류합니다. 보수적인 경로가 검증돼 있으면 그 조건 안에서만 진행할 수 있습니다. 웹 검수 환경에 로컬 검사기가 없는 경우와 게임 자체의 안전성이 미검증인 경우를 혼동하지 않습니다. 전자는 기존 규격을 따라 언어 결과를 반환하되 배치 검사 대기로, 후자는 초기 기술 보강 대상으로 구분합니다.

## 5. 3차의 실제 처리 흐름

```text
의미·캐릭터·뉘앙스 최종 수정
→ 게임별 확정 layout_profile과 진행 규격 확인
→ 실제 출력 조건을 재현하는 검사기로 픽셀 폭과 줄 수 계산
→ 허용된 동작·구간 안에서 한국어 줄바꿈 후보 생성
→ AI/검수자가 호흡·조사·어절·문장부호와 초과 행 검토
→ 수정 행 재계산 및 RSC·반각/전각·공백·보호 필드 별도 검사
→ 합격한 번역문과 배치만 최종 확정
```

픽셀 계산과 반복 검사는 로컬 검사기/렌더러가 맡고 AI는 의미와 어색한 끊김, 초과·예외 행에 집중합니다. 검사기나 필요한 글리프 폭 자료를 사용할 수 없으면 눈대중으로 합격 처리하지 않습니다. 웹 검수에서는 번역 수정 결과를 반환하고 로컬 배치 검증 대기로 구분합니다.

의미를 보존한 배치가 불가능하면 재검토 대상으로 남깁니다. 문장 삭제, 뒷부분 절단, 무단 폰트 축소, 대사창 확대, 페이지·대기 명령 삽입으로 억지 통과시키지 않습니다.

변수·이름 치환은 게임에서 확인된 길이 범위로 검사합니다. 치환 범위가 미확정이면 해당 조건은 미검증으로 남깁니다. 문장·폰트·크기·출력 규격·빌더 변경 시 관련 과거 합격값을 재사용하지 않고 재검증합니다.

## 6. 합격과 보고의 구분

언어 검수 완료, 화면 배치 검증 완료, RSC/구조 검증 완료, 실제 게임 검증 완료를 별도로 기록합니다. 대표 샘플만 실행했다면 테스트한 장면과 조건만 명시하며 전 대사 실행 성공으로 확대하지 않습니다.

출력은 기존 CSV 스키마를 유지합니다. 추가 배치 정보는 게임별 검수 프로그램이 지원하는 비고/상태값 또는 별도 결과 파일로 남기고 승인 없이 필수 컬럼을 변경하지 않습니다. 검수 프로그램과 Drive 자료 등록 시에도 판본별 출력/진행 규격을 연결하고, 규격이 없거나 금지된 변환이 있으면 최종 승인/적용을 보류합니다.

이 문서는 앞으로 수행할 검증 기준입니다. 문서가 존재한다는 사실은 검사기 구현이나 해당 게임의 `[n]` 안전성·픽셀 한계·RSC·구동 안정성이 이미 검증되었다는 뜻이 아닙니다.
