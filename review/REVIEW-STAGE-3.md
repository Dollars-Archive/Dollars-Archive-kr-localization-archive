# 3차 검수 지시문

> 현재 작업은 **3차 최종 정밀검수**다.
> 이 단계는 최종 CSV 반입 직전의 가장 엄격한 언어 검수와 최종 화면 배치를 담당한다.

## 목적

3차는 약 **500행 단위** 또는 더 작은 장면 묶음으로 범위를 줄여 문장 하나하나를 깊게 확인한다.

1차의 구조적 기준과 2차의 자연화 결과 데이터를 바탕으로 최종 품질을 만든다. 다른 단계 지시문을 읽거나 혼합하지 않는다.

[대사 번역 공통 원칙](DIALOGUE-TRANSLATION-POLICY.md)과 해당 게임에서 검증한 출력 규격을 사용한다.

**순서는 언어 최종 수정 → `[n]` 최종 재배치 → 픽셀 폭·최대 줄 수·RSC·구조 별도 검사다.**

## 우선 확인 항목

- 원문 의미의 정확성
- 미세한 오역
- 뉘앙스
- 앞뒤 대사 문맥
- 감정선의 연속성
- 복선
- 중의적 표현
- 농담과 언어유희
- 캐릭터 일관성
- 호칭과 관계
- 조사
- 어순
- 문장 리듬과 호흡
- 읽기 자연스러움
- 한국어 최종 문장에 맞는 `[n]` 배치
- 승인된 실제 폰트·크기·게임 출력 조건의 가로 픽셀 폭
- 대사창 종류별 최대 표시 줄 수와 자동 줄바꿈 동작
- 최종 RSC/문자열 제한과 그 실제 단위
- 태그·제어 코드·보호 필드
- 최종 CSV 유효성

## 작업 원칙

1. 공통 기준 자료를 다시 확인하되, 근거 없이 기존 확정 규칙을 뒤집지 않는다.
2. 관계/존대 규칙과 실제 문맥이 충돌하면 근거를 명시해서 수정 후보로 제시한다.
3. 한 문장만 보지 말고 가능하면 앞뒤 문맥과 장면 기능을 함께 본다.
4. 직역과 의역 중 어느 쪽이든 원문의 기능과 캐릭터성을 보존하는 쪽을 선택한다.
5. 캐릭터의 감정 변화와 관계 변화를 평평하게 만들지 않는다.
6. 최종 CSV에 들어갈 수 없는 구조적 변경은 하지 않는다.
7. 원문, ID와 보호 필드는 유지한다. 예외는 해당 게임에서 제거·이동이 안전하다고 검증된 번역 필드의 화면 배치용 `[n]`뿐이다.
8. 실제 플레이에서 사용자가 확정한 번역·줄바꿈을 자동 재작성하지 않는다. 출력 조건과 충돌하면 근거를 보고하고 재승인을 받는다.

## 선행 출력 규격 확인

게임별 `layout_profile` 또는 기존 동등 자료에서 다음의 검증 여부를 확인한다.

- 실제 폰트, 크기, 글자 전진 폭·자간·배율 등 렌더링 조건
- 가로 픽셀 한계와 최대 줄 수
- `[n]`이 없을 때 자동 줄바꿈 여부
- `[n]` 제거·이동이 진행·음성·연출에 영향을 주지 않는지
- 보호 명령과 재배치 가능한 구간
- RSC의 실제 제한 대상, 단위, 한계와 검사 방법
- 초과 및 긴 한글 대사의 실제 증상·안정성 검증 결과

이 규격을 새로 알아내는 것은 별도 기술 검증이다. 3차 검수 묶음마다 게임 구조를 재분석하지 않는다. 규격이 없거나 미확정이면 가능한 언어 검수만 진행하고 배치·안정성은 검증 대기로 남긴다.

Pretendard Bold를 승인한 작품은 그 작품의 실제 Pretendard Bold 렌더링 조건을 사용한다. 다른 작품에는 해당 작품의 승인 폰트를 사용한다. 글자 수만으로 픽셀 폭을 대신하지 않는다.

## 최종 줄바꿈과 검사 순서

1. 의미·말투·뉘앙스를 먼저 최종 수정한다.
2. 안전성이 확인된 화면 배치용 `[n]`만 대상으로 원문 위치에 얽매이지 않고 제거·재배치·생성한다. 자동 줄바꿈으로 충분한 경우 불필요한 `[n]`을 강제하지 않는다.
3. 로컬 검사기/렌더러가 실제 출력 조건으로 픽셀 폭과 표시 줄 수를 계산하고 가능한 줄바꿈 후보를 만든다.
4. AI/검수자는 한국어 문장 호흡, 조사·어절, 문장부호와 초과·예외 행을 확인한다.
5. 수정한 행은 다시 측정한다. 픽셀 폭, 최대 줄 수, RSC, 보호 명령 보존과 CSV 구조를 각각 검사한다.
6. 사용자가 확정한 값을 보호하면서 검사 근거가 있는 행만 최종 배치 합격으로 기록한다.

페이지 전환·대기·음성·연출·변수·분기 명령은 보존하고, 보호 명령이 기준으로 삼는 구간을 넘겨 문장이나 명령을 이동하지 않는다. 미확인 태그와 CSV의 실제 개행은 `[n]` 재배치 예외에 포함하지 않는다.

초과한다고 문장 뒷부분을 자르거나, 핵심 의미를 삭제하거나, 폰트를 무단 축소하거나, 대사창·페이지 명령을 임의 변경하지 않는다. 의미를 보존한 수정안 또는 기술 검토 대상으로 반환한다.

변수·이름 치환은 확인된 길이 범위로 검사하며 범위가 없으면 미검증으로 기록한다. 최종 문장, 폰트, 크기, 출력 규격 또는 빌더가 바뀌면 영향받은 행의 기존 합격을 재사용하지 않고 재검증한다.

웹 검수 환경에 검사기나 정확한 글리프 폭 자료가 없으면 눈대중으로 '폭 통과'라고 판정하지 않는다. 언어 결과와 미확정 배치 후보를 반환하고 Codex/로컬 검수 프로그램의 배치 검증 대기로 남긴다.

## 최종 출력 기준

3차 결과는 게임별 검수 프로그램으로 반입 가능한 스키마를 유지한다. **반입 가능과 최종 패치 적용 가능은 구분**하며 미해결 행은 거부 또는 격리한다.

최소 조건:

- 안정적인 행 ID와 원문 유지
- 필수 컬럼과 보호 필드 유지
- 한글 번역 필드 최종안 반영
- 한국어 기준 줄바꿈과 픽셀 폭·최대 줄 수 검사 결과
- RSC/문자열 제한 별도 검사 결과
- 검사한 번역문과 출력 규격 버전을 식별할 근거
- 미해결 행은 기존 상태값/비고 또는 별도 결과 파일로 표시

승인 없이 CSV 필수 컬럼을 새로 만들거나 행을 분할하지 않는다.

## 완료 기준

언어 검수 완료, 화면 배치 완료, RSC/구조 검증 완료, 실제 게임 검증 완료를 별도로 보고한다. 미검증 항목이 남으면 최종 합격으로 묶지 않는다.

```text
3차 언어 최종 수정
→ 최종 `[n]` 배치와 자동 제한 검사
→ 게임별 검수 프로그램 반입 및 미해결 행 격리
→ 합격한 패치 데이터 적용
→ 자동 검증
→ 실제 게임 플레이 검수
→ 사용자 확정값 축적
```

정적 픽셀 검사만으로 구동 안정성을 확정하지 않는다. 대표 장면만 실행했다면 테스트한 장면과 조건만 기록하며 전 대사 실행 성공으로 확대하지 않는다.

실제 플레이에서 확인된 수정은 `workflow/PLAYTEST-FEEDBACK-POLICY.md`의 우선순위를 따른다.
