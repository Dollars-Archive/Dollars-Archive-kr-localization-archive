# 웹 GPT 검수 데이터 스키마

이 문서는 1차·2차·3차 검수에서 공통으로 참조하는 게임별 기준 자료와 최종 CSV의 최소 규칙을 정의합니다.

언어와 화면 배치의 공통 원칙은 [DIALOGUE-TRANSLATION-POLICY.md](DIALOGUE-TRANSLATION-POLICY.md)를 따릅니다. 이 문서는 기존 게임별 CSV 스키마를 임의 변경할 권한을 부여하지 않습니다.

## 1. 공통 기준 파일

### `glossary.csv`

고정 용어를 관리합니다.

권장 항목:

```csv
source_term,approved_ko,category,notes,status
```

### `characters.csv`

캐릭터의 안정적인 성격·특징을 관리합니다.

권장 항목:

```csv
character_id,name,aliases,personality,traits,base_speech_style,verbal_habits,notes
```

### `relationships.csv`

화자 → 청자 방향 관계를 관리합니다.

A → B와 B → A는 서로 다른 행으로 관리할 수 있어야 합니다.

권장 항목:

```csv
speaker_id,listener_id,relationship,speech_level,address_rule,effective_from,effective_to,exceptions,notes
```

### `speech_style.csv`

캐릭터가 누구와 대화하는지와 별개로, 그 캐릭터 자체의 화법을 관리합니다.

권장 항목:

```csv
character_id,base_style,sentence_length,vocabulary_tendency,emotional_expression,avoid,approved_examples,notes
```

### ゲーム별 출력 규격 `layout_profile`

파일명·포맷은 프로젝트의 기존 구조를 따릅니다. JSON 등 별도 기준 파일로 관리할 수 있으며 검수 CSV에 새 필수 컬럼을 강제하지 않습니다.

필요한 개념:

- 게임 ID·판본·빌드 및 규격 버전
- 승인 폰트 식별값, 글리프 폭 자료, 크기·자간·배율·줄 높이·렌더링 조건
- 대사창 종류별 유효 가로 픽셀 한계와 최대 줄 수
- 자동 줄바꿈의 검증 상태와 동작
- 재배치 가능한 명령, 허용 구간, 검증 근거
- 보호 명령과 미확인 명령
- RSC의 제한 대상·단위·한계·계산 방법·검증 상태
- 변수 치환 길이 범위, 경계·초과·긴 대사 시험 결과
- 실제 실행 근거와 확인한 환경

미확정 항목은 미확정으로 둡니다. RSC의 의미나 픽셀 한계를 임의 추측하지 않습니다. Pretendard Bold는 그 폰트를 승인한 작품에서만 사용하며 다른 게임에 강제하지 않습니다.

## 2. 관계도와 말투를 분리하는 이유

다음 둘은 다른 정보입니다.

- 누구에게 존댓말/반말을 하는가
- 어떤 어휘와 리듬으로 말하는가

따라서 관계도와 캐릭터 말투를 하나의 값으로 합치지 않습니다.

## 3. 단계별 CSV 기본 규칙

게임마다 실제 컬럼은 달라질 수 있지만 다음 개념은 유지합니다.

- 변하지 않는 안정적인 행 ID
- 원문 필드
- 현재 한국어 번역 필드
- 필요한 경우 화자/청자 ID
- 보호해야 하는 제어 코드/태그/구조 필드
- 검수 상태
- 비고/근거
- 스키마 버전 또는 데이터 버전이 필요한 프로젝트에서는 명시적 버전 값

## 4. 보호 필드와 화면 배치 예외

번역 검수에서 다음 값은 임의로 재생성하거나 삭제하지 않습니다.

- 행 ID와 원문 필드 전체
- 페이지 전환·대기·음성·연출 등 보호 제어 코드와 태그
- 플레이스홀더
- 분기/이벤트 식별자
- 음성/캐릭터/장면 참조 ID
- 빌더가 요구하는 구조 필드
- 의미와 안전성이 확인되지 않은 명령

게임별 추가 보호 필드는 해당 프로젝트 규칙을 따릅니다.

**검증된 화면 배치 명령만 제한적으로 예외 처리합니다.** 해당 게임에서 `[n]`이 순수한 화면 줄바꿈이며 제거·이동이 안전하다고 검증되면, 번역 필드에서 한국어 문장에 맞게 제거·재배치·생성할 수 있습니다. 원문 필드의 `[n]`은 그대로 둡니다.

이 예외는 모든 태그의 개수·순서 검사를 생략하라는 뜻이 아닙니다. 검증된 배치 토큰만 게임별 허용 규칙으로 비교하고, 나머지 보호 토큰의 값·순서와 기준 대사 구간은 유지합니다. `[n]` 위치 또는 개수가 원문과 다르다는 이유만으로 승인된 배치를 손상으로 처리하지 않습니다.

페이지·대기·음성·연출 경계를 넘어 문장이나 토큰을 이동하지 않습니다. 토큰 `[n]`, CSV 레코드 개행, 따옴표로 감싼 셀의 실제 개행을 구분합니다. 파서에서 명령인지 일반 문자열인지 확인하지 않은 일괄 치환은 금지합니다.

사용자 확정 번역·줄바꿈과 고정 배치 예외는 보호합니다. 기술 규격과 충돌하면 재승인 대상으로 표시하고 자동으로 덮어쓰지 않습니다.

## 5. 최종 CSV 요구사항

3차 검수 결과 CSV는 게임별 검수 프로그램으로 결정론적으로 반입할 수 있어야 합니다. 반입 가능하더라도 미해결 행은 최종 패치 적용 대상에서 격리합니다.

반입 시 최소 확인:

1. 예상 스키마인가
2. 필수 컬럼이 존재하는가
3. 행 ID가 중복되지 않는가
4. 알려지지 않은 ID가 있는가
5. 원문과 보호 필드가 손상되지 않았는가
6. 보호 제어 코드/태그는 보존하고 배치 토큰만 승인된 예외 범위에서 바뀌었는가
7. 인코딩과 CSV 개행이 지원 형식인가
8. 최종 문장의 픽셀 폭과 최대 표시 줄 수가 해당 출력 규격을 통과했는가
9. RSC/파일·레코드·버퍼 제한을 실제 단위로 별도 검사했는가
10. 배치 검사 결과가 현재 번역문·폰트·출력 규격·빌드 조건에 대응하는가

검수 프로그램은 이상한 행을 추측해서 고치기보다 **거부 또는 격리**하고 사용자가 확인할 수 있게 합니다.

배치 결과는 기존 스키마의 비고/상태값 또는 별도 검사 결과 파일로 보존합니다. 권장 기록은 행 ID, 번역문 식별값, 출력 규격 버전, 줄별 픽셀 폭, 표시 줄 수, 배치·RSC·보호 필드의 개별 결과, 실패 이유와 검사 근거입니다.

언어 완료, 배치 완료, RSC/구조 완료, 실제 게임 검증을 구분합니다. 측정하지 않은 행을 합격 처리하지 않으며, 폰트·크기·문장·출력 규격·빌더 변경 시 영향받은 기존 합격을 재검증합니다.

## 6. 단계 간 데이터 전달

권장 흐름:

```text
원장/현재 번역
→ 1차 기초 규칙·판정 결과
→ 2차 한국어 문장 결과, 최종 배치 미확정
→ 3차 언어 최종 수정 및 배치·제한 검사
→ 게임별 검수 프로그램
```

각 단계는 이전 단계의 결과와 게임별 확정 출력 규격을 입력으로 받을 수 있지만, 다른 단계의 지시문까지 함께 가져오지는 않습니다.

웹 검수 환경에서 정확한 폭 계산 도구를 사용할 수 없으면 언어 결과를 반환하고 로컬 배치 검증 대기로 남깁니다. 최종 배치 합격을 추정해 기록하지 않습니다.
