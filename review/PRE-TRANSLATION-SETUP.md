# 번역 전 기준자료·용어집 선세팅 정책

이 문서는 **전체 일본어 원장과 카테고리, 게임 전용 검수 프로그램이 준비된 뒤** 대량 번역 직전에 수행하는 언어 0단계 정책입니다.

## 0단계보다 먼저 충족할 엔지니어링 선행조건

0단계 언어 기준자료를 프로젝트 시작 직후 상상으로 만들지 않습니다. 다음 순서를 먼저 통과합니다.

```text
최소 한글 출력
→ 출력·진행 안전성 시험
→ 전체 일본어 원문 추출
→ 안정 row_key 부여
→ category/subcategory 분류
→ 게임 전용 검수 프로그램 준비
→ 0단계 언어 기준자료 구축
```

출력·진행 안전성은 [출력·진행 안전성 사전검증](../workflow/EARLY-TEXT-RUNTIME-GATE.md)을 따릅니다. 가로 픽셀 폭·조건부 표시량·최대 줄 수·자동 줄바꿈, `[n]` 유지/삭제/이동/추가/개수 변경, 반각/전각·공백·문장부호, RSC/인코딩과 다음 대사·선택지·다음 장면 진행을 실제 게임에서 확인합니다.

원장은 단순 문장 목록이 아니라 최소한 `row_key`, 일본어 원문, `category`, `subcategory`, 가능하면 화자/청자와 보호 제어문자 정보를 가져야 합니다. `row_key`는 번역문이 바뀌어도 안정적으로 같은 레코드를 가리켜야 합니다.

게임 전용 검수 프로그램은 용어집 최종화보다 먼저 준비합니다. 기본 구조는 `D:\Codex\# 검수 프로그램\EVE 고스트 에너미즈`, 카테고리/세부분류 방식은 `D:\Codex\# 검수 프로그램\이상한 환상향 로터스 라비린스`를 참고할 수 있지만 게임별 데이터는 섞지 않습니다.

# 핵심 원칙

**전체 원장과 문자열 기능을 본 상태에서 용어집·캐릭터·관계·말투를 만들고, 그다음 대량 대사 번역을 시작합니다.**

관계는 화자 → 청자 방향별입니다. `A → B = 반말`, `B → A = 존댓말` 같은 비대칭 관계를 정상 케이스로 취급하며 `서로 반말` 같은 대칭 가정을 기본값으로 두지 않습니다.

---

## 1. 고정 검수 파이프라인

```text
최소 한글 출력 + 출력·진행 안전성 게이트
→ 전체 일본어 원문 추출 + 안정 row_key + category/subcategory
→ 게임 전용 검수 프로그램
→ 0단계 기준자료·용어집
→ Google Drive 최신 용어집·필수파일·분류 CSV 등록/동기화/재조회
→ 1차: 전체 대사집을 1,000행 단위로 기초 검수
→ 2차: 1차 결과 전체를 다시 1,000행 단위로 자연화·말투 검수
→ 3차: 2차 결과 전체를 다시 500행 단위로 최종 정밀검수
→ <게임약칭>_최종대사_수정_누적.csv
→ 게임별 검수 프로그램 최신 원장 반입
→ 모드/패치 생성
→ 실제 게임 플레이 검증
```

각 차수는 전체 대사집을 다시 훑는 별도 패스이며 작업 묶음 크기만 1,000 / 1,000 / 500으로 다릅니다.

## 2. 대량 번역 시작 전 필수 기준자료

최소한 다음 자료를 게임별로 먼저 준비합니다.

### 고정 용어집

- 캐릭터명·별칭·칭호
- 장소·지역·던전명
- 아이템명
- 시스템 용어
- 스펠·기술명
- 조직·종족·세계관 용어
- 반복적으로 등장하는 핵심 명사

각 항목에는 가능하면 다음을 남깁니다.

```text
일본어 원문
승인 한국어
분류
근거 출처
확정 / 임시 / HOLD 상태
비고
```

### 캐릭터 기준표

최소 권장 정보:

```text
character_id
일본어 공식명
승인 한국어명
별칭·애칭·칭호
성격
기본 말투
1인칭
2인칭/호칭 습관
자주 쓰는 어미·말버릇
감정 표현 경향
피해야 할 표현
승인 예시
근거 출처
확정 상태
```

### 관계도

관계는 **화자 → 청자 방향**으로 관리합니다.

```text
A → B
B → A
```

는 서로 다른 규칙일 수 있습니다.

최소 권장 정보:

```text
speaker
listener
관계
반말 / 존댓말
호칭
상대에 따른 말투
적용 시작/종료 구간
예외
실제 대사 또는 자료 근거
확정 상태
```

### 말투표

- 기본 문장 길이
- 어휘 성향
- 고풍/어린아이/무뚝뚝/정중/독설 등 특징
- 1인칭·2인칭
- 말버릇
- 감정 표현 강도
- 피해야 할 평준화 표현
- 승인 예시 대사

## 3. 캐릭터 이름 조사 순서

캐릭터 이름은 다음 순서로 조사합니다.

1. **사용자가 이미 확정한 프로젝트 표기**
2. **공식 홈페이지·공식 게임·공식 설정 자료**
3. 공식 자료가 일본어뿐이고 한국어 표기가 애매하면 **나무위키의 통용 한국어 표기**를 참고
4. 나무위키에도 없거나 근거가 부족하면 **일본 위키·팬 위키·사전·작품별 자료를 교차 확인**
5. 그래도 애매하면 임의 확정하지 않고 `HOLD`

공식 일본어 이름을 무시하고 영어판 철자만 보고 한국어명을 만들지 않습니다.

공식 한국어 표기가 실제로 존재하면 그것을 우선 검토합니다.

---

## 4. 캐릭터 성격·말투 조사

오래된 게임은 당시 자료가 남아 있는 경우가 많으므로 적극적으로 조사합니다.

우선 조사 대상:

- 공식 캐릭터 소개
- 게임 내 실제 일본어 대사
- 공식 홈페이지
- 매뉴얼·설정집·공략본
- 당시 연재 기사·소개 기사·인터뷰·특집 자료
- 시리즈 공식 자료

보조 자료:

- 나무위키의 성격·인물관계 정리
- 일본 위키·팬 위키의 캐릭터 설명

나무위키와 일본 위키는 **조사 시작점과 교차검증 자료**로 사용할 수 있습니다.
실제 게임 일본어 원문이나 공식 자료와 충돌하면 실제 원문·공식 자료가 우선합니다.

---

## 5. 일본어판과 영어판이 함께 있을 때

**일본어 원문을 기준으로 용어와 대사를 번역합니다.**

영어판은 보조자료입니다.

```text
대사 의미      → 일본어 원문 기준
용어           → 일본어 원문 기준
존대/반말      → 일본어 원문 기준
호칭           → 일본어 원문 기준
캐릭터 말투    → 일본어 원문 기준
영어판         → 의미 확인·문맥 보조·고유명 철자 확인
```

일본어와 영어가 충돌하면 일본어를 따릅니다.

영어판에서 추가·삭제·순화·과장된 농담, 욕설, 설명, 비유를 한국어판에 자동으로 가져오지 않습니다.

---

## 6. 용어 통일은 최우선 합격 조건

대사 번역 전에 **용어 통일 기준을 최대한 고정**합니다.

- 동일 인물의 이름·별명·칭호가 장면마다 흔들리지 않게 합니다.
- 아이템·스킬·던전·시스템·세계관 용어를 통일합니다.
- 같은 일본어 원어·같은 개념이면 승인된 한국어 용어를 우선합니다.
- 비슷해 보여도 다른 일본어 원어를 무조건 하나의 한국어로 뭉치지 않습니다.
- 새 반복 용어를 발견하면 한 행만 고치고 끝내지 말고 용어집 등록 후보로 올립니다.
- 용어집이 실제 일본어 원문과 충돌하면 기존 용어집이라는 이유만으로 자동 KEEP하지 않습니다.
- 사용자가 확정한 용어는 AI가 취향 판단만으로 다시 변경하지 않습니다.

---

## 7. 반말·존댓말·호칭을 번역 전에 강하게 고정

주요 등장인물 사이의 관계는 가능한 한 번역 시작 전에 확정합니다.

반드시 확인:

- A가 B에게 반말인지 존댓말인지
- B가 A에게는 어떤지
- 이름 / 성 / 별명 / 직책 / 씨 / 님 등 호칭
- `さん / さま / ちゃん / くん` 등의 실제 기능
- 처음 만났을 때와 친해진 뒤 변화
- 공적인 자리와 사적인 자리 차이
- 상하관계·연령·조직·가족·친밀도
- 특정 사건 이후 관계 변화
- 예외적인 감정 상태에서만 말투가 무너지는지

자료가 부족하면 실제 일본어 대사의 `です/ます`, 보통체, 명령형, 1·2인칭, 이름 접미사와 호칭을 확인합니다.

근거 없이 관계를 추정해 전체 대사에 적용하지 않습니다.
불확실하면 `HOLD` 또는 `provisional`로 남깁니다.

---

## 8. Google Drive 등록 및 1차 시작 합격 게이트

로컬에서 0단계 기준자료 초안을 만들었다는 이유만으로 `0단계 완료` 또는 `1차 시작 가능`이라고 판정하지 않습니다.

Google Drive의 PC 동기화 상위 루트는 다음입니다.

```text
F:\내 드라이브\검수 프로그램
```

게임별 실사용 구조는 다음 세 역할을 기본으로 합니다.

```text
<게임명>\
├─ 01_최신_용어집
├─ 02_검수_필수파일
└─ 03_검수_수정_CSV
```

기존 게임 폴더가 다른 이름/세부구조를 이미 사용하면 중복 생성이나 강제 재배치 없이 동일 역할의 기존 폴더를 사용합니다.

1차 검수 전에 반드시 확인합니다.

- `01_최신_용어집`에 최신 용어 기준과 confirmed/provisional/HOLD 상태가 반영됨
- `02_검수_필수파일`에 캐릭터·말투·방향별 관계/존대/호칭, HOLD/출처, layout_profile과 `[n]`·반각/전각·가로폭·최대 줄 수·RSC 규칙이 있음
- 1차 1,000행, 2차 1,000행, 3차 500행 지시문이 물리적으로 분리되어 있음
- `03_검수_수정_CSV`에 최신 원장에서 내보낸 검수 CSV가 있고 `row_key`, 일본어 원문, `category`, `subcategory`가 유지됨
- Google Drive 동기화가 완료됨
- 등록한 파일을 다시 읽어 실제 반영을 확인함

로컬만 준비된 상태는 `LOCAL_DRAFT_ONLY`, Drive 반입/동기화가 남은 상태는 `DRIVE_REGISTRATION_PENDING`으로 기록합니다. Drive 접근이 불가능하면 로컬 파일만으로 정상 완료 처리하지 않습니다.

Drive 작업공간의 목적은 **PC를 켜두지 않고 휴대폰/웹 ChatGPT에서 검수할 수 있게 하는 것**입니다. 3차 완료 후 로컬 검수 프로그램으로 돌아오는 핵심 산출물은 `<게임약칭>_최종대사_수정_누적.csv`입니다.

## 9. 각 검수 단계의 역할

### 1차: 1,000행

기초공사입니다.

- 구조·태그·누락
- 화자/청자
- 관계도·반말/존댓말·호칭
- 캐릭터 말투의 명백한 위반
- 용어 통일
- 명백한 오역
- 이미 검증된 `[n]`·반각/전각·공백 보호 규칙의 명백한 위반
- 새 용어·관계·말투 후보 등록

최종 자연화와 최종 픽셀 줄바꿈은 맡기지 않습니다. 초기 출력 시험을 새로 수행하는 단계도 아닙니다.

### 2차: 1,000행

1차 기준을 유지한 상태에서 자연스러운 한국어와 캐릭터다운 말투를 만듭니다.

- 일본어 직역투 제거
- 캐릭터 어휘·리듬
- 감정 강도
- 장면 흐름과 대사 연결
- 허용 구간에서 원문의 `[n]` 위치에 끌려가지 않는 한국어 문장 완성

최종 화면 배치는 아직 확정하지 않습니다. 안전성이 확인되지 않은 `[n]` 변환이나 반각/전각 정규화는 하지 않습니다.

### 3차: 500행

가장 꼼꼼한 최종 정밀검수입니다.

- 미세 오역·뉘앙스
- 복선·중의성·농담
- 감정선·캐릭터 일관성
- 조사·어순·호흡
- 게임별로 허가된 동작만 적용하는 최종 `[n]` 배치
- 승인 폰트 기준 실제 픽셀 폭
- 최대 표시 줄 수
- 반각/전각·공백 보존, RSC와 보호 명령

세부 화면 배치 규칙은 `review/DIALOGUE-TRANSLATION-POLICY.md`와 `review/REVIEW-STAGE-3.md`를 따릅니다. 변경 시 진행이 깨지는 조건은 3차에서도 보존합니다.

# 한 줄 원칙

**번역량보다 먼저 기준을 만든다. 초기 출력·진행 안전성과 용어·캐릭터·관계·존대를 선세팅한 뒤 1차 1,000행 → 2차 1,000행 → 3차 500행 정밀검수로 진행한다.**
