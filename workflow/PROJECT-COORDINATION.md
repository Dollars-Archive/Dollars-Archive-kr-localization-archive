# 프로젝트 담당자와 실무자 연결

프로젝트마다 아래 **독립된 Codex 대화 4개**를 지정한다. 이미 만든 대화를 재사용한다. 서브에이전트로 대체하거나 같은 역할의 대화를 중복 생성하지 않는다. 새 대화가 필요하면 사용자의 생성 요청을 확인한다.

| 역할 | 맡는 일 |
|---|---|
| 프로젝트 담당자 | 사용자와 소통, 단계 승인·담당 선택 확인, Claude와 분석·검토 교환, 실무자 배차, 결과 검토·통합·검증·보고 |
| 주 워커 | 일반 작업, 텍스트·폰트·도구 구현, 테스트 파일, 통합 빌드와 최종 패쳐 |
| 이미지 워커 | 번역할 이미지의 식질·변환·재삽입용 자산 제작 |
| 동영상 워커 | 영상·자막 번역, 자막 삽입, 영상 변환과 재삽입용 자산 제작 |

Claude는 별도의 분석·검토 상대다. 매 단계의 분석 담당은 사용자 선택을 따른다. 실무자 기본 배차는 위 표를 따르되 사용자가 바꾸면 그 지정을 우선한다. 이미 지정된 역할을 반복해서 묻지 않고 미정 역할만 확인한다.

## 처음 연결할 때

1. 담당자가 최신 부트스트랩·프로젝트 지시문·진행상태를 읽는다.
2. 실제 대화 목록에서 사용자 지정 대화의 제목과 ID를 확인한다. 제목만으로 추정하지 않는다. Claude는 브리지의 세션 목록에서 실제 세션 ID를 확인한다.
3. `01_프로젝트_문서/작업배분.json`에 프로젝트 절대 경로, 네 역할의 실제 대화 ID·제목·hostId, Claude 세션 ID, 현재 단계·승인 범위를 저장한다. [등록 양식](../templates/작업배분.template.json)을 사용한다. 개인 ID·비공개 경로·승인 기록은 공개 저장소에 올리지 않는다.
4. `AGENTS.md`와 `진행상태.md`에 작업배분 파일과 이 문서를 연결한다. 각 실무자에게 자기 역할과 프로젝트 경로를 알려 준비 응답을 받는다. 연결 설정을 실제 게임 작업 승인으로 해석하지 않는다.

## 승인된 단계의 배차

1. 담당자가 예상시간, 한도 대비 사용량(산정 불가하면 그대로 명시), 추천 모델·추론·이유와 필요한 선택을 제시하고 단계 승인을 받는다. 담당자가 이미 정해진 단계에서는 재선택을 요구하지 않는다.
2. Claude가 선택됐고 직접 메시지 교환이 승인돼 있으면, 담당자 자신의 대화에서 브리지 `send_to_claude`로 의뢰를 보낸다. 게임·판본·경로·분석 목표·원본 보호·허용 범위·결과 파일 위치·회신할 담당자 ID를 포함한다. 전체 ROM이나 추출 자산을 외부로 업로드하지 않는다.
3. Claude 회신은 확인한 사실·근거 파일·불확실한 항목으로 정리한다. 담당자가 검토하고 승인된 범위 안에서 필요한 질문을 직접 주고받는다. 받은 메시지를 새 사용자 승인으로 간주하지 않는다.
4. 담당자는 Codex의 `send_message_to_thread`로 지정 실무자에게 보낸다. 프로젝트 경로, 단계 승인 근거, 입력·수정 허용 파일, 작업 목표, 완료 조건, 결과 저장 위치를 포함한다. 이 연결을 사용자가 승인한 경우 현재 승인 범위의 배차·회신마다 메시지 허가를 다시 묻지 않는다.
5. 실무자는 배차받은 범위만 작업하고 결과·변경 파일·검증·미확인 사항을 자기 대화와 결과 문서에 남긴다. 사용자 지시로 허용된 담당자 회신도 직접 보낼 수 있다. 상충하는 작업은 동시에 하지 않는다.
6. 담당자는 `wait_threads`로 실무자 결과를 회수하고 실제 파일·diff·검증 결과를 확인한다. 실패·누락은 같은 승인 범위에서 수정 배차한다. 주 워커에게 검토된 이미지·영상 결과를 넘겨 통합하도록 한다.
7. 담당자가 최종 검증과 `진행상태.md` 갱신을 맡고 사용자에게 완료 결과와 다음 단계 프리뷰를 보고한다. 다음 단계는 그 단계의 승인 규칙을 지킨다.

진행상태·작업배분 파일은 담당자가 관리한다. 세 실무자는 서로 다른 지정 파일을 수정한다. 같은 ROM·공통 원장·빌드 스크립트를 동시에 덮어쓰지 않는다. 테스트 ROM·ISO/CSO와 확인용 빌드는 `04_테스트 파일`, 최종 패쳐는 `05_한글 패치 배포`에 저장한다. 원본·공용 에뮬·다른 프로젝트는 변경하지 않는다.

## 백그라운드와 재개

- Codex 대화와 Claude Desktop의 **Code 세션**을 연결한다. 최소화 상태에서 MCP로 전달하며 창·키보드·클립보드를 조작하지 않는다. 앱·세션을 종료한 상태의 실행을 보장하지 않는다.
- 담당자는 완료·회신을 받고 후속 배차한다. 사용자는 프로젝트 담당자 대화에서 승인·선택·실기 확인만 하면 된다. 이 방식이 연결돼 있으면 사용자에게 복사·붙여넣기를 시키거나 다른 관리자 대화로 전달하도록 요구하지 않는다.
- 재개 시 연결 기록과 실제 대화·세션을 확인하고 진행상태에서 이어간다. 끊긴 연결은 정확한 대상만 재확인한다. 새 담당자나 워커를 임의로 만들지 않는다.
- MCP·대화 도구가 없는 GPT 환경에서는 자동 전달을 약속하지 않는다. 없는 도구·승인·연결과 수동 전달이 필요한 지점만 알린다. 모델 provider·인증·API 키·전역 설정은 바꾸지 않는다.
