# 관제센터 프로젝트·워커 자동 준비 절차

## 대상과 승인 범위

관제센터에서 신규 한글화 프로젝트 준비를 명시적으로 지시하고 준비 범위를 승인한 경우의 동작 규약이다. 실행은 관제센터의 프로젝트 준비 기능이 담당한다. 문서 추가와 실행 기능 구현·실증은 구분한다. 미구현 버전에서는 준비 대기로 안내한다.

예: **“PSP 시크릿 게임 한글패치 작업 준비해줘.”** 프로젝트명·기종과 관제센터에서 선택한 총괄을 사용한다. 생성 대상에 영향을 주는 동명 프로젝트·역할 충돌만 확인한다. 원본이 없으면 작업 공간·역할을 준비한 뒤 원본 투입 대기로 끝낸다.

| 대상 | 기준 |
| --- | --- |
| 작업 공간 | 사용자가 지정한 위치의 폴더 한 개. 기존 원본·성공 자료·세이브·공용 폴더는 보존한다. |
| 총괄 | 사용자가 선택한 Codex 또는 Claude 한 명. 양쪽에 총괄을 중복 배치하지 않는다. |
| 실무 워커 | 주·이미지·동영상 역할의 독립된 Codex 대화 세 개. 서브에이전트로 대체하지 않는다. |
| 상대 앱 | 양쪽 앱 참여를 요청했거나 운영 방식에 필요한 협업 대화. 등록된 기존 세션은 재사용한다. |
| 운영 문서 | 선택한 부트스트랩에 필요한 AGENTS.md·CLAUDE.md·시작하기.md·진행상태.md·역할 등록 자료. |

같은 작업 폴더 사용, 각 앱의 프로젝트 등록, 대화·세션 생성, 실제 작업 가능한 연결 상태를 각각 확인한다. Claude 일반 채팅용 Projects와 Code 탭의 로컬 세션을 혼동하지 않는다.

## 준비 순서

1. **요청 기록·중복 확인:** 준비 요청의 고유 식별자, 프로젝트 경로, 선택 총괄, 승인 범위를 관제센터에 저장한다. 재요청은 이미 만든 폴더·프로젝트·대화·역할을 조회해 이어간다.
2. **사전 점검:** 실제 호출할 공식 실행 파일의 버전·도움말, 기존 로그인, 지원 프로토콜, 브리지를 확인한다. PATH의 CLI와 Desktop 내장 엔진은 버전이 다를 수 있다. 자동 설치·업데이트·로그인 변경은 별도 승인 없이 하지 않는다.
3. **작업 공간 확보:** 대화 작업 디렉터리에 필요한 최소 프로젝트 루트를 먼저 확보한다. 총괄·기본 워커를 준비한 뒤 1단계에서 기본 폴더·문서를 정리한다. 신규 준비 요청으로 기존 프로젝트의 읽기 전용 제한을 해제하지 않는다.
4. **Codex 준비:** 지원되는 공식 앱 기능 또는 설치된 app-server 프로토콜로 프로젝트와 대화를 각각 준비한다. 반환된 실제 식별자·작업 폴더를 대조한다. 실험적 프로젝트 API는 설치 버전의 스키마와 실행 가능 여부를 확인해 사용한다.
5. **Claude Code 준비:** 공식 CLI 세션 생성과 Desktop 연결을 별도로 처리한다. 승인된 준비용 요청에서 실제 반환된 세션 식별자를 확인한다. Desktop으로 이어갈 때는 실행 중인 CLI/백그라운드 세션의 중복 재개를 피하고, 공식 재개 경로로 같은 세션이 실제 표시·연결됐는지 확인한다. CLI 성공만으로 Desktop 연결을 완료 처리하지 않는다.
6. **등록·준비 응답:** 실제 반환·조회한 식별자, 제목, 폴더, 역할, 연결 상태를 로컬의 `01_프로젝트_문서/작업배분.json`과 관제센터에 기록한다. 역할별 준비 응답도 별도로 확인한다.
7. **결과 보고:** 생성됨·재사용됨·등록 확인·준비 응답 수신·연결 대기를 구분한다. 확인된 범위만 준비 완료로 보고한 뒤 기존 12단계 작업·지시·중간보고·보완·반려·승인 흐름으로 이어간다.

## 공식 호출의 구분

- **Codex:** app-server의 `thread/start`는 새 대화, `turn/start`는 실제 작업 시작이다. 독립 워커는 별도 대화로 같은 프로젝트에 연결한다. 설치 버전에 실험적 `project/create`·`project/import`와 대화의 `projectId` 연결이 있어도 실제 생성·앱 표시 확인 전에는 등록 완료로 간주하지 않는다. [공식 app-server 문서](https://learn.chatgpt.com/docs/app-server)를 참고한다.
- **Claude Code:** 공식 CLI의 `--session-id`·`--name`·구조화 출력·명시적 재개 기능을 사용한다. Desktop 연결 옵션 `--desktop`은 v2.1.285 이상과 지원 플랫폼·구독 로그인이 필요하다. 지원 환경에서는 `claude --desktop --resume <세션 식별자>`로 기존 CLI 세션을 이어갈 수 있다. 이 명령에 초기 작업 지시나 임의의 다른 옵션을 함께 붙이지 않는다. [CLI 문서](https://code.claude.com/docs/en/cli-reference)와 [Desktop 문서](https://code.claude.com/docs/en/desktop#coming-from-the-cli)를 따른다.
- **기존 브리지:** 세션 조회·메시지 전달 기능을 새 세션 생성 API라고 간주하지 않는다. 실제 송신 대화의 신원을 확인하는 승인된 MCP 연결을 사용한다. 연결 실패·거절을 비공개 IPC 조작이나 송신자 가장으로 우회하지 않는다. 메시지 전달과 담당자 응답도 구분한다.

## 실패·권한·정보 보호

- 일부만 성공하면 성공한 대상을 보존하고 실패 항목부터 재개한다. 시간 초과로 생성 여부가 불명확하면 먼저 조회해 대조하며, 곧바로 새 대화·워커를 또 만들지 않는다.
- 기존 OpenAI native provider·구독 로그인과 Claude 로그인·사용자 모델 선택을 유지한다. 토큰·API 키를 추출·저장하지 않는다. 구독 기반 실행과 별도 유료 API 사용을 혼동하지 않는다.
- 기존 작업 지시에 ‘준비’라는 말이 있다는 이유로 새 대화 생성 금지·원본 보호 범위를 해제하지 않는다. 신규 프로젝트 준비 요청과 승인 범위를 별도로 식별한다.
- ROM 분석·번역·이미지·자막 작업·게임 실행·Drive 변경·공개 업로드는 별도 범위다. 준비만 요청받았다면 역할·문서 준비에서 멈춘다.
- 개인 경로·비공개 링크·대화 및 세션 식별자·인증 정보는 공개 GitHub·배포물에 넣지 않는다.
