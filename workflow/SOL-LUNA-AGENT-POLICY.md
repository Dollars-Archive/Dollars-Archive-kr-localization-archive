# 한글화 모델 라우팅 정책

> 파일명은 기존 호환을 위해 `SOL-LUNA-AGENT-POLICY.md`를 유지합니다.
> 현재 정책의 핵심은 **Sol High는 감독관, DevSpace의 Web GPT-5.6 Sol XHIGH는 기본 전문 실무 책임자**라는 점입니다.

## 1. 현장 조직도

이 한글화 프로젝트의 모델 역할은 시설관리 조직처럼 구분합니다.

| 역할 비유 | 모델 | 기본 책임 |
|---|---|---|
| 소장 / 감독관 | **GPT-5.6 Sol / High** | 전체 파악, 계획, 작업 분해, 배차, 위험 판단, 결과 검증, 충돌 해결, 최종 통합 |
| 전기·기계·소방 과장 / 분야별 실무 책임자 | **DevSpace Tunnel → Web GPT-5.6 Sol / XHIGH** | 일반~상당 난도의 실제 분석·구현·설계·조사·검토를 맡는 기본 전문 실무자 |
| 기사 / 단순 작업자 | **GPT-5.6 Luna / XHIGH** | 범위와 방법이 확정된 단순·반복·기계 작업, 저위험 검사·정리·테스트 |
| 외주 전문업체 | **GPT-6 Astra / Medium** | 내부 실무진이 맡기 불안하거나 해결하기 어려운 고난도 구현·디버깅 |
| 최고급 외부 전문가 | **DevSpace Tunnel → Web GPT-6 Pro** | Astra급 접근으로도 풀기 어렵거나 최고 수준 추론이 필요한 난제 |

Terra는 기본 워크플로에서 사용하지 않습니다.

이 표는 단순 성능 순위가 아니라 **업무 책임과 비용·위험을 나누는 조직도**입니다.

## 2. 최우선 원칙: Sol High는 소장이지 기본 실무자가 아니다

Sol High는 프로젝트를 전반적으로 이해하고 필요하면 직접 처리할 능력이 있지만, 그것이 Sol이 모든 실무를 직접 해야 한다는 뜻은 아닙니다.

Sol의 기본 업무:

- 사용자 요구 해석
- 프로젝트 상태 파악
- 작업 목표와 성공 조건 정의
- 작업을 독립 가능한 하위 작업으로 분해
- 각 하위 작업의 위험도·난이도 판정
- 적합한 작업자 배차
- 작업자 결과 회수
- 서로 충돌하는 결과 판단
- 실제 diff·테스트·런타임 근거 검증
- 최종 통합과 사용자 보고

**`Sol도 할 수 있다`, `Sol이 이미 문맥을 안다`, `Sol이 금방 끝낼 수 있다`만으로 전문 실무 위임을 생략하지 않습니다.**

Sol 사용량 절감은 정당한 위임 이득입니다. 인계 비용이 합리적인 비자명한 프로젝트 실무라면 기본적으로 전문 실무자에게 넘깁니다.

Sol이 직접 실행까지 맡는 것은 주로 다음 예외입니다.

- 작업 분해·배차·판정·최종 검토 자체
- 사용자와의 짧은 의사결정
- 위임 프롬프트보다 작은 명백한 초소형 수정
- 다른 작업자의 결과를 합치는 짧은 통합 수정
- 적합한 작업 경로를 실제로 사용할 수 없고, 수동 handoff보다 즉시 직접 처리하는 편이 명백히 나은 작은 작업

**상당한 프로젝트 실무를 Sol이 직접 수행하기로 했다면 시작 전에 구체적인 예외 이유가 있어야 합니다. 단순히 `내가 할 수 있어서`는 이유가 아닙니다.**

## 3. 기본 전문 실무자: DevSpace + Web GPT-5.6 Sol XHIGH

비자명한 한글화 실무의 기본 책임자는 **DevSpace Tunnel을 통해 프로젝트에 접근하는 Web GPT-5.6 Sol XHIGH**입니다.

대표 업무:

- 게임 파일·자산 구조 조사
- 기존 프로젝트 코드와 성공 자산 분석
- 추출기·빌더·패처·검수 도구의 일반 구현
- 중간~상당 난도의 버그 원인 분석
- 여러 파일을 묶은 기술 조사
- 데이터 구조와 변환 경로 분석
- 구현안 비교와 기술 설계 검토
- 프로젝트 규칙에 따른 실질적인 코드/문서 작업
- Sol이 계속 붙잡고 있을 필요가 없는 전문 검토

작업이 프로젝트 파일을 실제로 다루는 비자명한 실무라면 Sol은 **먼저 Web Sol XHIGH에 맡길 수 있는지 확인하는 쪽이 기본**입니다.

`Web Sol XHIGH는 Luna보다 조금 어려운 일을 하는 보조 모델`로 취급하지 않습니다. **한글화 현장의 기본 분야별 과장, 즉 주력 실무 책임자**입니다.

Web Sol XHIGH의 결과도 최종 승인값은 아닙니다. Sol High가 실제 프로젝트 상태와 테스트를 재확인한 뒤 통합합니다.

## 4. Luna XHIGH: 기사에게 맡길 수 있는 안전한 잡일만

Luna는 범위·방법·완료 조건이 이미 확정된 **저위험 기계 작업**에 적극 사용합니다.

좋은 예:

- 파일 목록과 문자열 위치 조사
- 확정 패턴 전수 검색
- CSV/JSON/Markdown 정리
- 단순 포맷 변환
- 확정 규칙에 따른 반복 수정
- 테스트 반복 실행
- 해시·크기·개수 비교
- 로그 집계
- 후보 목록 생성
- 이미 정해진 체크리스트의 기계적 검증

Luna에게 맡기지 않는 예:

- 새로운 아키텍처 설계
- 바이너리 구조를 처음부터 추론하는 작업
- 불명확한 런타임 문제의 핵심 원인 판단
- 캐릭터 관계·존대·말투의 애매한 최종 판정
- 근거가 갈리는 번역/용어 결정
- 안전성 증거 없이 대량 파일을 수정하는 작업
- 승인된 규칙을 재정의하는 작업

쉽게 말해 **조명 교체는 맡기되 도면 해석과 고장 원인 설계 판단까지 기사에게 떠넘기지 않습니다.**

Luna 결과 중 판단이 필요한 부분은 Web Sol XHIGH 또는 Sol High로 올립니다.

## 5. Astra Medium: 외주 전문업체

Astra Medium은 내부 실무진에게 맡기기 불안한 고난도 구현·디버깅 전문입니다.

대표 업무:

- 복잡한 바이너리·실행 파일 구조 분석
- 여러 계층이 얽힌 저장/로드·런타임 프리징
- 까다로운 패처·빌더 구현
- 구조적 설계 결함 진단
- 재현은 되지만 원인이 복합적인 디버깅
- 메모리·런타임·직렬화 등 여러 영역을 가로지르는 문제

기본적으로 Web Sol XHIGH 실무 범위를 넘어서는 문제에서 호출합니다.
다만 처음부터 명백히 외주 전문업체급 난이도라면 Web Sol이나 Luna를 일부러 실패시킨 뒤 호출하지 않고 **바로 Astra를 배차할 수 있습니다.**

## 6. Web GPT-6 Pro: 최고급 외부 전문가

다음 상황에서 사용합니다.

- Astra급 접근으로도 원인이 설명되지 않음
- 기존 가정을 처음부터 뒤집어 재검토해야 함
- 여러 합리적인 구현/분석이 모두 실패함
- 매우 깊은 바이너리·런타임·세이브·알고리즘 추론이 필요함
- 비용이 더 들더라도 독립적인 최고 수준 분석이 필요한 상황

보통은 `Web Sol XHIGH → 필요 시 Astra → 필요 시 Web GPT-6 Pro` 순으로 올라갑니다.
다만 이미 확보된 증거만으로 최고 전문가급 문제임이 명백하면 불필요한 실패 단계를 만들지 않고 바로 Pro를 고려할 수 있습니다.

Pro 결과 역시 Sol이 실제 파일과 테스트에 대조합니다.

## 7. 작업 시작 시 배차 절차

비자명한 한글화 프로젝트 작업을 받으면 Sol은 **직접 실행부터 시작하지 않고 먼저 배차 가능성을 확인**합니다.

기본 흐름:

```text
사용자 요청
→ Sol High가 목표·제약·성공 조건 파악
→ 독립 하위 작업으로 분해
→ 단순·기계·저위험 작업은 Luna XHIGH
→ 일반~상당 난도 전문 실무는 DevSpace + Web GPT-5.6 Sol XHIGH
→ 고난도 구현·디버깅은 Astra Medium
→ 최고난도 난제는 DevSpace + Web GPT-6 Pro
→ Sol High가 결과 재검증·충돌 해결·통합
```

작업 시작 시 다음을 내부적으로 확인합니다.

1. 이 작업에 실제 전문 실무가 있는가?
2. Web Sol XHIGH에 독립적으로 맡길 수 있는가?
3. 기계적인 부분을 Luna로 떼어낼 수 있는가?
4. 처음부터 Astra급 또는 Pro급 문제인가?
5. 서로 독립적인 하위 작업이 2개 이상이면 병렬 실행이 가능한가?

**상당한 작업인데 모든 실무를 Sol 혼자 수행한다면, 위 다섯 항목을 검토한 뒤에도 위임하지 않은 구체적인 이유를 결과 보고에 남깁니다.**

## 8. DevSpace Tunnel / Web GPT 운용

Web Sol XHIGH 또는 Web GPT-6 Pro에 프로젝트 실무를 맡길 때 연결 상태를 추측하지 않습니다.

Web GPT-5.6 Sol XHIGH의 실제 Oracle/DevSpace 경로, 검증된 파일 작업 범위와 삭제·이동 금지선은 `workflow/WEB-SOL-DEVSPACE-OPERATING-CONTRACT.md`를 함께 따릅니다. **Oracle의 기본 예시가 Latest를 사용한다는 이유만으로 GPT-5.6 Sol을 지원하지 않는다고 판단하지 않습니다.** 현재 검증된 지정 경로는 `gpt-5.6-sol / extra-high / select`이며, 지원 불가 판정은 실제 실행 근거가 있을 때만 내립니다.

계정 로그인·MFA·계정 전환·계정 전역 메모리/개인화·앱/권한/OAuth 설정은 사용자만 처리합니다. 반면 Oracle이 소유한 **현재 임시채팅 탭의 맞춤화/개인화 상태 확인과, 정확한 비활성 제어 1개를 식별했을 때 그 임시채팅 안에서만 활성화하는 동작**은 계정 전역 설정 변경이 아니며 검증된 `ensureTemporaryChatPersonalization` 계열 helper가 자동 처리할 수 있습니다. `chatgpt-workspace-setup` 또는 다른 스킬의 `user handles account personalization` 문구를 이 임시채팅 토글까지 확대해석하여 사용자에게 매 run 수동 조작을 요구하지 않습니다. 정확한 제어가 없거나 모호하거나 로그인/MFA/계정 수준 변경이 필요할 때만 자동 조작을 중단하고 사용자에게 실제 막힌 지점을 요청합니다.

1. 정확한 프로젝트 루트를 확인합니다.
2. **DevSpace Tunnel의 `open_workspace`를 실제 호출합니다.**
3. 성공한 workspace를 기준으로 Web GPT 작업을 진행합니다.
4. 실제 자동 전달 기능이 있으면 자동 전달합니다.
5. 자동 전달이 불가능하거나 사용자 동작이 필요한 경우 Sol이 완성된 수동 handoff 프롬프트를 준비합니다.

### DevSpace 오류 판정

- `tool disabled` / `FORBIDDEN`
  - 네트워크 장애로 추측하지 않습니다.
  - 현재 ChatGPT/Codex 세션에서 developer MCP 사용이 활성화되지 않은 상태로 판정합니다.
  - DevSpace 재설치, Tailscale, Watchdog, OAuth 변경을 임의로 지시하지 않습니다.
- `502` / `network_error`
  - MCP 연결 경로 문제 가능성으로 봅니다.
  - **최소 1분 간격으로 최대 5회 재시도**합니다.
  - 그 뒤에도 실패할 때만 연결 경로 조사 또는 사용자 확인으로 넘어갑니다.

실제 `open_workspace` 호출 없이 연결 여부를 단정하지 않습니다.

## 9. Web GPT 작업자 역할 고정과 1회 안전장치

Web GPT 미션에는 다음 역할을 명시합니다.

```text
당신은 이 미션을 직접 수행하도록 호출된 최종 작업 수행자다.
별도 지시가 없는 한 Oracle이나 다른 GPT를 호출하지 마라.
호스트 Codex/Oracle의 실행 완료를 기다리지 마라. 호스트가 바로 당신의 응답을 기다리고 있을 수 있다.
지정된 프로젝트 자료와 허용된 외부 조사 범위 안에서 작업을 직접 수행하고 결과를 반환하라.
직접 수행할 수 없다면 다른 작업자에게 재위임하지 말고 현재 막힌 이유와 필요한 입력만 반환하라.
```

다음 역할 혼동은 동일 미션 자동 재위임을 **1회에서 종료**합니다.

- 다시 Oracle 또는 다른 GPT를 호출하려 함
- 호스트 완료를 기다림
- 중첩 호출이 프로젝트 락에 막힘
- 지정 작업을 하지 않고 다시 상위 작업자에게 반환
- 실질 결과 없이 역할 혼동으로 종료

이 경우 Sol은 자동 재호출을 멈추고 **완성된 manual handoff 프롬프트**를 사용자에게 제공합니다.

이 규칙은 DevSpace의 `502` / `network_error` 재시도 규칙과 별개입니다.

## 10. 위임 손익 규칙

이 정책에서 **Sol 사용량 절감 자체가 실질적인 위임 이득**입니다.

전문 실무를 Web Sol XHIGH에 맡길 수 있는데 단지 Sol이 할 수 있다는 이유로 위임을 생략하지 않습니다.

위임하지 않는 합리적인 예외:

- 작업 자체가 handoff 설명보다 작은 초소형 작업
- 작업이 아직 너무 불명확해서 먼저 Sol의 짧은 범위 확정이 필요함
- 동일 파일에 대한 동시 쓰기 때문에 해당 순간에는 순차 작업이 필요함
- 실제 작업 경로가 제공되지 않아 위임 자체를 실행할 수 없음

**같은 파일을 다룬다는 이유는 병렬 쓰기를 금지하는 근거이지, 전문 실무를 처음부터 끝까지 Sol이 혼자 해야 한다는 근거가 아닙니다.** 조사·분석·검토는 분리하거나 순차 위임할 수 있습니다.

## 11. 병렬 작업

작업을 받은 즉시 독립적으로 분리 가능한 하위 작업이 2개 이상인지 확인합니다.

- 독립적이면 병렬 배차를 적극 사용합니다.
- 같은 파일/같은 staging에 동시 쓰기는 금지합니다.
- 앞 작업 결과가 다음 작업 입력이면 순차 실행합니다.

예:

```text
Web Sol XHIGH → 패처 구조 분석
Luna XHIGH → 기존 문자열/파일 위치 전수 조사
Luna XHIGH → 테스트 로그 집계
```

## 12. 작업자 결과 반환 규칙

작업자는 가능하면 다음을 반환합니다.

- 확인된 사실
- 재현 가능한 근거
- 조사/수정한 파일
- 변경 내용
- 실행한 테스트와 실제 결과
- 실패한 접근
- 미해결 사항
- 다음 작업에 필요한 입력

`완료했습니다`만으로 완료로 인정하지 않습니다.

## 13. Sol 최종 검토

Sol은 다른 작업자의 결과를 받은 뒤 최소한 다음을 확인합니다.

1. 범위 준수
2. 다른 프로젝트 침범 여부
3. 사용자 확정값 보존
4. 실제 diff 또는 변경 파일
5. 테스트 결과
6. 기존 성공 자산 보존
7. 필요한 런타임 검증
8. 최종 산출물 재조회

```text
AI 응답 완료 ≠ 구현 완료 ≠ 정적 검증 완료 ≠ 실제 게임 검증 완료
```

## 14. 실제 플레이 확정값 보호

우선순위:

1. 사용자가 실제 플레이 중 직접 확인하고 확정한 수정
2. 게임 내 실제 문맥과 대사 근거
3. 등록된 원장/용어집/관계/말투 규칙
4. AI 분석 또는 자동 분석

어떤 작업자도 1번을 AI 판단만으로 덮어쓰지 않습니다.

## 15. 모델 또는 기능을 사용할 수 없을 때

- 정해진 모델/추론 강도를 다른 모델로 조용히 대체하지 않습니다.
- `Latest`가 기본 경로라는 문서만 보고 Web GPT-5.6 Sol XHIGH를 미지원으로 판정하지 않습니다. CLI 거부, 실제 웹 모델 선택 실패, UI 미지원 또는 실행 오류처럼 관측된 근거를 확인합니다.
- 로그인·임시채팅 개인화 실패는 모델 미지원과 구분합니다.
- 검증된 Web Sol XHIGH 경로가 막혀도 Codex Sol XHIGH나 다른 모델로 임의 대체하지 않습니다.
- Web Sol XHIGH에 맡길 상당한 실무인데 자동 경로만 막힌 경우, 가능한 경우 **manual handoff를 먼저 준비**합니다.
- 아주 작은 작업만 Sol이 직접 흡수합니다. 상당한 전문 실무를 연결 실패 하나만으로 자동으로 Sol에게 몰아주지 않습니다.
- Astra나 Pro가 실제로 제공되지 않으면 실행했다고 가장하지 않습니다.
- 새 유료 API나 외부 공급자를 사용자 승인 없이 시작하지 않습니다.
