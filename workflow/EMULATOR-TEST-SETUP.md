# 모든 한글화 프로젝트의 전용 에뮬 공통 설정

이 설정은 신규·진행 중 모든 한글화 프로젝트에 같은 기준으로 적용한다. 3단계에서 수행하며, 설정 확인 후 4번 롬 분석으로 넘어간다. 이미 설정된 프로젝트는 실제 값과 확인 기록을 점검한다.

## 경로와 확인 순서

1. 사용자가 `00_원본`에 원본 롬, `09_전용_에뮬`에 포터블 에뮬을 복사했는지 확인한다. 복사 전에는 등록 대기와 넣을 경로를 안내한다.
2. 설정·메모리카드·세이브·게임별 설정이 프로젝트 안에 저장되도록 분리한다. 공용 설정과 기존 세이브는 보존한다.
3. 에뮬의 기본 롬 탐색 폴더·게임 목록 경로를 해당 게임의 `04_테스트 파일`로 설정한다. 원본 롬은 `00_원본`에 보존하고 테스트 롬을 `04_테스트 파일`에 만든다. 테스트 파일이 아직 없어도 경로는 이 폴더로 지정한다.
4. 아래 키보드 배치와 기본 패드 매핑을 **모두 적용한다**. 에뮬레이터 자체의 일시정지·재개 단축키를 지정할 수 있으면 **Space(스페이스)**로 설정한다. 키보드 설정을 새로 작성할 때 에뮬의 기존 패드 매핑을 삭제하거나 키보드 항목만으로 덮어쓰지 않는다. 에뮬마다 버튼 이름이 달라도 위치와 기능을 기준으로 대응한다. 지원하지 않는 버튼·스틱은 생략하고 대응 결과를 기록한다.
5. 설정 파일을 저장하고 다시 읽는다. 에뮬을 재실행해 경로와 키보드·패드 매핑이 모두 유지되는지 확인한다. 키보드와 패드의 실제 입력은 각각 확인한다. 패드가 미연결이면 기본 매핑은 보존·준비하고 실제 패드 입력 확인만 대기로 남긴다. 직접 실행할 수 없으면 사용자 확인 대기로 남긴다. 설정을 쓰기만 한 상태를 실행 확인 완료로 표시하지 않는다.
6. 확인 기록과 다음 작업 프리뷰를 보고한다. 완료 후 4단계 분석 담당(Claude/Codex)을 확인한다.

## 기본 키보드 배치

| 컨트롤러 기능·위치 | 키보드 |
|---|---|
| 방향키 위 / 아래 / 왼쪽 / 오른쪽 | ↑ / ↓ / ← / → |
| 페이스 버튼 위 / 왼쪽 / 아래 / 오른쪽 | W / A / S / D |
| L1 또는 L / L2 / L3(왼쪽 스틱 누르기) | Q / Z / F |
| R1 또는 R / R2 / R3(오른쪽 스틱 누르기) | E / C / G |
| Select 또는 Back / Start | N / M |
| 왼쪽 스틱 위 / 왼쪽 / 아래 / 오른쪽 | U / H / J / K |
| 오른쪽 스틱 위 / 왼쪽 / 아래 / 오른쪽 | P / L / `;`(세미콜론) / `'`(작은따옴표) |

페이스 버튼은 명칭 대신 **화면상의 위치**를 기준으로 맞춘다. 예를 들어 PS의 △/□/×/○는 W/A/S/D이다. 불확실한 버튼 대응은 추측하지 않고 해당 에뮬에서 확인한다. 추가 기능 키는 이 기본 배치와 충돌하지 않게 정한다.

진행상태에는 에뮬·버전, 실행 경로, 롬 탐색 경로, 설정·세이브 경로, 키보드·패드 버튼 대응·생략 항목, 패드 기기·입력 백엔드, 재실행 후 설정 유지·각 입력 확인 결과를 기록한다. 다른 프로젝트에서도 같은 키보드 배치와 패드 매핑 원칙을 기본으로 사용한다. 사용자에게 매번 키를 하나씩 입력하라고 요구하지 않는다.


## 에뮬레이터 자체 일시정지·재개

- 일시정지·재개(Pause/Resume 또는 Toggle Pause) 단축키를 변경할 수 있는 에뮬은 **Space(스페이스)**로 설정한다.
- 게임 내부의 일시정지나 컨트롤러 Start 입력과는 별개다. 위 기본 배치의 Start는 **M**으로 유지한다.
- Space가 다른 에뮬 기능에도 할당되어 있으면 중복 실행되지 않도록 충돌을 정리한다. 단축키 변경을 지원하지 않으면 기존 키를 유지하고 실제 일시정지 키를 안내한다.
- 기존 설정 저장·재실행 확인 때 이 단축키의 유지 여부도 함께 확인하고, 진행상태와 사용자 키 안내에 반영한다.

## 기본 패드 매핑

- **패드 매핑은 기본 작업에 포함한다.** 사용자가 별도로 패드를 요청할 때까지 생략하지 않는다. 정상적인 에뮬 기본 매핑이 있으면 보존·확인하고, 비어 있거나 빠진 항목은 추가한다.
- 페이스 버튼은 글자 이름보다 **물리적 위치**로 대응한다. PS △ / □ / × / ○는 Xbox 패드의 Y / X / A / B(위 / 왼쪽 / 아래 / 오른쪽)에 대응한다. Nintendo 패드처럼 같은 글자라도 위치가 다른 기기는 실제 위치를 확인한다.
- 방향키는 방향키, 왼쪽·오른쪽 스틱은 해당 스틱에 대응한다. L/R 또는 L1/R1은 LB/RB, L2/R2는 LT/RT, L3/R3는 스틱 누르기, Select/Start는 Back·View / Start·Menu에 대응한다. 대상 기종이 지원하지 않는 입력은 생략하고 기록한다.
- 예를 들어 PSP는 △/□/×/○, 방향키, 아날로그 스틱, L/R, Select/Start를 모두 준비한다. PSP에 없는 오른쪽 스틱·L2/R2를 필수로 만들지 않는다.
- 실제 연결된 기기와 에뮬이 지원하는 입력 백엔드(XInput·SDL·DInput 등)를 확인한다. 장치 번호나 버튼 번호를 확인 없이 임의로 확정하지 않는다. 미연결이면 에뮬의 지원되는 기본 매핑을 보존·준비하고, 기기 감지·입력 시험은 확인 대기로 기록한다.
- 키보드와 패드는 함께 사용할 수 있게 유지한다. 프로젝트 전용 설정만 변경하며 공용 에뮬 설정과 다른 프로젝트의 사용자 매핑은 건드리지 않는다.
- 설정 파일의 저장·재읽기와 재실행 후 매핑 유지를 확인한다. 패드 연결 시 방향키·페이스 버튼·스틱·숄더·Start/Select 입력을 대상 기종 범위에서 확인하고, 키보드만 시험한 결과로 패드 입력까지 정상이라고 보고하지 않는다.

## 테스트 빌드 바로 실행

테스트 ROM·ISO/CSO를 만들 때는 ISO만 제공하지 않고 **해당 빌드를 바로 부팅하는 실행용 `.cmd`를 같은 테스트 폴더에 함께 만든다.** `09_전용_에뮬`의 실제 실행 파일과 해당 테스트 ROM을 연결하고, 더블클릭하면 에뮬레이터 실행과 게임 부팅까지 이어지도록 게임·에뮬별로 확인한 실행 인자를 사용한다. 공백·한글 경로를 인용하고 파일 존재를 확인하며, 어느 빌드를 실행하는지 파일명·안내에 명시한다. 에뮬만 열리고 게임 선택을 다시 요구하는 실행기는 완료로 보지 않는다. `.cmd` 작성·정적 확인과 실제 부팅 확인은 구분해 기록한다.
