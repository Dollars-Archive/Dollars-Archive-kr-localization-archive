# 공개 작업일지 운영 표준

게임 한국어화 프로젝트의 진행 상황을 공개적으로 기록할 때 사용하는 기본 운영 표준입니다.

이 문서의 목적은 저장소 방문자가 **현재 이 게임의 한국어화 작업이 진행 중인지**, 그리고 **최근 어떤 성과가 있었는지** 쉽게 확인하게 하면서도, 실제 제작에 사용한 내부 기술 노하우는 공개하지 않는 것입니다.

핵심 원칙은 한 문장으로 정리합니다.

> **성과는 공개하고, 레시피는 공개하지 않는다.**

---

## 1. 적용 대상

이 표준은 아래 프로젝트에 적용합니다.

- 새로 시작하는 게임 한국어화 프로젝트
- 이미 진행 중이며 앞으로 공개 작업일지를 운영할 프로젝트
- 첫 배포 전 진행 상황을 공개하고 싶은 프로젝트
- 배포 후에도 업데이트·버그 수정·검수 보완 기록을 계속 남길 프로젝트

아직 후보 조사만 하는 게임에는 적용하지 않습니다. 실제 작업 시작이 확정되기 전에는 README에 `작업 진행 중` 표시를 넣거나 `WORKLOG.md`를 억지로 만들지 않습니다.

### 소급 적용 제외

다음 두 저장소는 이미 최종 패치가 배포된 프로젝트이므로 이 표준을 소급 적용하지 않습니다.

- `Dollars-Archive/eve-rebirth-terror-kr-patch`
- `Dollars-Archive/eve-ghost-enemies-kr-patch`

두 저장소의 README에 작업 진행 중 안내를 추가하거나, 과거 기록을 복원하기 위한 `WORKLOG.md`를 새로 만들지 않습니다.

---

## 2. 기본 구조

게임별 공개 작업일지는 저장소 루트의 **`WORKLOG.md` 단일 파일**로 운영합니다.

```text
<game-repository>/
├─ README.md
└─ WORKLOG.md
```

날짜별 개별 파일은 기본값으로 만들지 않습니다.

새 기록은 항상 `WORKLOG.md`의 기존 날짜 기록보다 위에 추가해 **최신 날짜가 맨 위**에 오도록 합니다.

모든 날짜에 억지로 기록하지 않습니다. 실제로 공개할 만한 의미 있는 작업이 있었던 날만 추가합니다.

---

## 3. README 작업 진행 중 선언

게임의 실제 한국어화 작업을 공식적으로 시작한 시점부터 README 상단에 아래 안내를 둘 수 있습니다.

```md
> [!IMPORTANT]
> ## 🚧 한국어화 작업 진행 중
> 현재 이 게임의 한국어 패치를 제작하고 있습니다.
>
> 작업 과정과 진행 상황은 공개 작업일지에 기록합니다.
> 세부 분석 방법과 내부 제작 노하우는 공개하지 않습니다.
>
> 📓 [작업일지 보기](WORKLOG.md)
```

이 안내의 목적은 저장소 방문자가 바로 아래 두 가지를 알 수 있게 하는 것입니다.

1. 현재 실제 한국어화 작업이 진행 중이다.
2. 공개 가능한 진행 상황은 `WORKLOG.md`에서 볼 수 있다.

후보 조사 단계에서는 이 선언을 사용하지 않습니다.

---

## 4. WORKLOG.md 기본 형식

새 프로젝트에서는 `templates/WORKLOG.template.md`를 복사해 시작합니다.

기본 형태:

```md
# 작업일지

> 이 문서는 한국어 패치 제작 진행 상황을 기록합니다.
> 세부 분석 방법 및 내부 제작 노하우는 공개하지 않습니다.

---

## YYYY-MM-DD

### 오늘 한 작업
- 한국어화 작업 시작

### 진행 상황
🟡 작업 진행 중

### 다음 목표
- 다음 공개 목표를 기록
```

기존 진행 프로젝트에 처음 적용할 때는 과거 일지를 억지로 복원하지 않습니다. 적용 시점의 날짜부터 시작하고, 필요하면 첫 항목에 현재 상태만 짧게 요약합니다.

---

## 5. 공개 가능한 내용

공개 작업일지는 **사용자 관점의 성과와 진행 상황**을 기록합니다.

예:

- 게임 데이터 구조 분석 진행
- 한국어 출력 테스트 진행
- 대사 추출 작업 진행
- UI 한글화 작업 진행
- 폰트 표시 테스트 진행
- 패처 제작 진행
- 실제 플레이 검수 진행
- 특정 진행 불가 문제 수정
- PC / Android / Nintendo Switch 환경 테스트
- 번역 또는 검수 범위 확대
- 배포 준비 진행

내부적으로 훨씬 복잡한 분석을 했더라도 공개 일지에서는 결과를 한 단계 추상화합니다.

예를 들어 내부적으로 특정 함수와 문자열 처리 경로를 추적했다면 공개 일지에는 다음 정도로 적습니다.

```text
저장·불러오기 화면에서 발생하던 프리징 문제의 원인을 확인하고 수정 작업 진행
```

---

## 6. 공개 금지 내용

`WORKLOG.md`에는 아래 내용을 기록하지 않습니다.

- 정확한 메모리 주소, 오프셋, 함수 주소
- 재현 가능한 바이너리 내부 구조와 세부 분석
- 패치 알고리즘의 구체적인 구현 방법
- 내부 분석 스크립트 또는 자동화 스크립트의 코드와 동작 원리
- 자체 검수 프로그램의 핵심 구현 기법
- 우회 기법, 후킹 지점, 패치 포인트 등 재현 가능한 세부 방법
- 리버스 엔지니어링 과정에서 확보한 핵심 제작 노하우
- 비공개 툴의 내부 구조와 설정
- 개인 정보, 계정 정보, 키, 토큰, 비공개 경로
- 원본 게임 데이터 또는 저작권상 공개하면 안 되는 자료

공개 일지는 기술 인수인계 문서가 아닙니다. 내부 구현을 다시 만들 수 있을 정도의 상세 정보가 필요하면 공개 `WORKLOG.md`가 아닌 게임별 비공개 작업 자료에 남깁니다.

---

## 7. 상태 표기

상태가 필요할 때는 아래 정도만 사용합니다.

- `🟡 작업 진행 중`
- `🔵 검수 진행 중`
- `🟢 배포 준비 중`
- `✅ 배포 완료`

근거가 명확하지 않은 진행률 퍼센트는 기본적으로 사용하지 않습니다.

---

## 8. 기존 프로젝트 적용 규칙

이미 진행 중인 프로젝트에 이 표준을 새로 적용할 때는 다음 원칙을 따릅니다.

1. 과거 작업일지를 전부 복원하지 않는다.
2. 적용 시점부터 기록한다.
3. 첫 항목에 현재까지의 상태를 짧게 요약할 수 있다.
4. 과거 기술 노하우를 공개 일지로 옮기지 않는다.
5. 이미 최종 배포가 끝난 프로젝트에 단지 형식을 맞추기 위해 소급 적용하지 않는다.

예:

```md
## 2026-09-13

### 작업 시작 기록
기존에 진행 중이던 한국어화 작업의 공개 작업일지를 오늘부터 기록합니다.

현재는 대사·UI 분석과 실제 플레이 검수를 병행하고 있습니다.
```

---

## 9. 배포 이후 운영

첫 배포가 완료되어도 `WORKLOG.md`는 삭제하지 않습니다.

이 문서는 프로젝트의 제작 역사로 유지합니다. 이후 다음 작업이 발생하면 같은 파일 맨 위에 새 날짜 기록을 추가합니다.

- 패치 업데이트
- 번역 수정
- 버그 수정
- 플랫폼 호환성 개선
- 검수 보완
- 패처 개선

Release Notes가 **무엇이 배포되었는지**를 기록한다면, Worklog는 **프로젝트가 어떤 흐름으로 진행되었는지**를 기록합니다.

---

## 10. GitHub Pages 연동 원칙

`WORKLOG.md` 공개에 GitHub Pages는 필수가 아닙니다.

초기 기본값은 README와 `WORKLOG.md`만 사용합니다. 이후 게임별 Pages를 정비할 때 필요하면 `작업일지` 메뉴를 추가할 수 있습니다.

Pages를 추가하더라도:

```text
WORKLOG.md = 단일 원본
GitHub Pages = 사용자용 표시 화면
```

구조를 유지합니다. Pages용 HTML에 작업일지 내용을 별도로 중복 작성하지 않습니다.

---

## 11. 새 프로젝트 적용 체크리스트

실제 게임 한국어화 작업 시작을 선언하는 시점에 다음을 확인합니다.

1. `templates/WORKLOG.template.md`를 게임 저장소 루트의 `WORKLOG.md`로 복사
2. 첫 날짜를 실제 작업 시작 또는 공개 일지 적용 날짜로 변경
3. 공개 가능한 첫 작업 내용을 기록
4. README 상단에 `🚧 한국어화 작업 진행 중` 안내 추가
5. README에서 `WORKLOG.md` 링크 제공
6. 이후 의미 있는 작업이 있는 날마다 최신 날짜를 맨 위에 추가
7. 공개 전 각 기록에 내부 제작 노하우가 섞이지 않았는지 확인

이 표준의 목적은 작업 과정을 감추는 것이 아니라 **진행 상황은 충분히 보여주면서 핵심 제작 노하우는 보호하는 것**입니다.
