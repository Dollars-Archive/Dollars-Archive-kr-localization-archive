# Public Localization Worklog Design

## 목적

각 게임 한국어화 저장소에서 배포 전부터 **현재 작업 중인 프로젝트임을 공개적으로 알리고**, 그날 진행한 작업을 사용자에게 읽기 쉬운 형태로 누적 기록한다.

이 작업일지는 기술 문서가 아니라 **공개 제작일지 / 진행 현황판**이다. 무엇을 했는지는 보여주되, 어떻게 했는지에 해당하는 내부 제작 노하우는 공개하지 않는다.

## 기본 구조

각 게임 저장소의 루트에 `WORKLOG.md` 하나를 둔다.

```text
<game-repository>/
├─ README.md
└─ WORKLOG.md
```

날짜별 개별 파일은 만들지 않는다. 기록은 `WORKLOG.md` 하나에 최신 날짜가 위로 오도록 계속 추가한다.

## README 공개 선언

작업을 공식적으로 시작한 게임 저장소의 README 상단에는 짧은 진행 중 안내를 둔다.

권장 형태:

```md
> [!IMPORTANT]
> ## 🚧 한국어화 작업 진행 중
> 현재 이 게임의 한국어 패치를 제작하고 있습니다.
>
> 작업 과정과 진행 상황은 공개 작업일지에 기록합니다.
> 세부 분석 방법과 내부 제작 노하우는 공개하지 않습니다.
>
> 📓 [작업일지 보기](WORKLOG.md)
```

목적은 저장소 방문자가 즉시 아래 두 가지를 알 수 있게 하는 것이다.

1. 이 게임은 현재 한국어화 작업이 진행 중이다.
2. 자세한 진행 상황은 `WORKLOG.md`에서 볼 수 있다.

## WORKLOG.md 형식

문서 상단에는 작업일지의 성격을 짧게 설명한다.

```md
# 작업일지

> 이 문서는 한국어 패치 제작 진행 상황을 기록합니다.
> 세부 분석 방법 및 내부 제작 노하우는 공개하지 않습니다.
```

각 날짜 기록은 최신 날짜를 맨 위에 추가한다.

기본 형식:

```md
## YYYY-MM-DD

### 오늘 한 작업
- 사용자에게 공개해도 되는 수준의 진행 내용

### 진행 상황
🟡 작업 진행 중

### 다음 목표
- 다음 공개 목표
```

모든 날짜에 억지로 기록하지 않는다. 실제로 의미 있는 작업이 있었던 날만 추가한다.

## 공개해도 되는 내용

공개 일지는 **성과와 진행 상황 중심**으로 작성한다.

예:

- 게임 데이터 구조 분석 진행
- 한국어 출력 테스트 진행
- 대사 추출 작업 진행
- UI 한글화 작업 진행
- 폰트 표시 테스트 진행
- 패처 제작 진행
- 실제 플레이 검수 진행
- 특정 진행 불가 문제 수정
- PC / Android / Nintendo Switch 환경 테스트
- 번역 또는 검수 범위 확대
- 배포 준비 진행

내부적으로 훨씬 더 복잡한 분석을 했더라도 공개 일지에서는 사용자 관점의 결과만 남긴다.

## 공개하지 않는 내용

아래 항목은 `WORKLOG.md`에 기록하지 않는다.

- 정확한 메모리 주소, 오프셋, 함수 주소
- 바이너리 내부 구조를 재현할 수 있는 상세 분석
- 패치 알고리즘의 구체적인 구현 방법
- 내부 분석 스크립트 또는 자동화 스크립트의 코드와 동작 원리
- 자체 검수 프로그램의 핵심 구현 기법
- 우회 기법, 후킹 지점, 패치 포인트 등 재현 가능한 세부 방법
- 리버스 엔지니어링 과정에서 확보한 핵심 제작 노하우
- 비공개 툴의 내부 구조와 설정
- 개인 정보, 계정 정보, 키, 토큰, 비공개 경로
- 원본 게임 데이터 또는 저작권상 배포하면 안 되는 자료

원칙은 다음 한 문장으로 요약한다.

> **성과는 공개하고, 레시피는 공개하지 않는다.**

## 표현 방식

공개 작업일지는 일반 사용자도 읽을 수 있어야 한다.

기술적으로는 매우 구체적인 작업이라도 다음처럼 한 단계 추상화해서 기록한다.

내부 기록:

```text
특정 함수와 문자열 버퍼 처리 경로를 추적해 프리징 원인을 수정
```

공개 작업일지:

```text
저장·불러오기 화면에서 발생하던 프리징 문제의 원인을 확인하고 수정 작업 진행
```

## 상태 표기

상태 표기는 필요할 때 아래 정도만 사용한다.

- `🟡 작업 진행 중`
- `🔵 검수 진행 중`
- `🟢 배포 준비 중`
- `✅ 배포 완료`

세부 퍼센트는 근거가 명확한 경우가 아니면 사용하지 않는다.

## 배포 이후 운영

첫 배포가 완료되어도 `WORKLOG.md`는 삭제하지 않는다.

이 문서는 프로젝트의 제작 역사로 유지한다. 이후 다음 작업이 발생하면 계속 같은 문서 맨 위에 날짜를 추가한다.

- 패치 업데이트
- 번역 수정
- 버그 수정
- 플랫폼 호환성 개선
- 검수 보완
- 패처 개선

Release Notes가 **무엇이 배포되었는지**를 기록한다면, Worklog는 **배포되기 전까지 어떤 흐름으로 작업이 진행되었는지**를 기록한다.

## 새 프로젝트 기본 적용

새 게임 한국어화 저장소를 만들고 실제 작업 시작을 선언하는 시점에 아래를 기본 세트로 적용한다.

1. 루트에 `WORKLOG.md` 생성
2. 첫 날짜 항목에 `작업 시작` 기록
3. README 상단에 `🚧 한국어화 작업 진행 중` 안내 추가
4. README에서 `WORKLOG.md` 링크 제공
5. 이후 의미 있는 작업이 있는 날마다 최신 날짜를 맨 위에 추가

아직 실제 작업을 시작하지 않은 후보 저장소에는 억지로 작업 진행 중 표시를 넣지 않는다.

## 기존 프로젝트 적용

이미 진행 중인 게임에 이 표준을 새로 적용할 경우, 과거 작업을 억지로 전부 복원하지 않는다.

적용 시점의 날짜부터 시작하고, 필요한 경우 첫 항목에 현재까지의 상태를 짧게 요약한다.

예:

```md
## 2026-09-13

### 작업 시작 기록
기존에 진행 중이던 한국어화 작업의 공개 작업일지를 오늘부터 기록합니다.

현재는 대사·UI 분석과 실제 플레이 검수를 병행하고 있습니다.
```

## GitHub Pages

`WORKLOG.md` 공개에 GitHub Pages는 필수 조건이 아니다.

초기 기본값은 README와 `WORKLOG.md`만 사용한다. 이후 해당 게임 저장소의 Pages를 정비할 때 필요하면 `작업일지` 메뉴를 추가할 수 있다.

Pages를 추가하더라도 `WORKLOG.md`를 단일 원본으로 유지하고, 웹 페이지는 이를 표시하는 프런트엔드 역할만 맡긴다.

## 완료 기준

이 표준이 구현된 상태는 다음을 만족해야 한다.

- 새 한국어화 프로젝트를 시작할 때 `WORKLOG.md`가 기본 구성으로 생성된다.
- README에는 작업 진행 중 선언과 작업일지 링크를 쉽게 추가할 수 있는 표준 문구가 있다.
- 작업일지는 단일 파일에 최신 날짜순으로 누적된다.
- 공개 가능한 진행 상황과 비공개 제작 노하우의 경계가 문서화되어 있다.
- 배포 후에도 작업일지를 프로젝트 역사로 유지한다.
- 기존 한글화 부트스트랩 문서와 템플릿에서 이 표준을 참조할 수 있다.
