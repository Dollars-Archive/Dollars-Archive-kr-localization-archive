# 한글화 프로젝트 전체 라이프사이클 재정의 설계

## 목적

새 게임 한글화 작업에서 `프로젝트 폴더 생성 → 롬 분석 → 최소 한글 출력 → 진행 안전성 검증 → 전체 원문 추출/분류 → 게임 전용 검수 프로그램 → 번역 전 0단계 → Google Drive 검수 작업장 → 1·2·3차 검수 → 최종 CSV 반입 → 모드 제작/실기 검수` 순서를 강제한다.

이 설계의 핵심은 **대량 번역 전에 기술적 진행 가능성과 검수 가능한 데이터 구조를 먼저 완성하는 것**이다. 한글 출력만 성공했다고 번역을 시작하지 않고, 전체 원문·안정 ID·카테고리·검수 프로그램이 준비된 뒤에야 언어 기준자료와 Google Drive 검수 환경을 완성한다.

기존 프로젝트에는 이 구조를 소급 강제 재배치하지 않는다. 기존 성공 자산과 현재 루트를 존중하고, 부족한 게이트와 연결 규칙만 보강한다.

---

## 1. 신규 프로젝트 기본 루트와 필수 폴더

게임이 정해지면 다른 실작업보다 먼저 다음 루트를 만든다.

```text
D:\Codex\한글화 프로젝트\<게임명>\
├─ 01_프로젝트_문서
├─ 02_한글화_작업
├─ 03_검수_프로그램
├─ 04_최종_배포
├─ 05_HD Pack
└─ 버그 리포트
```

용도:

- `01_프로젝트_문서`: 분석 보고서, 설계, 결정 기록, 인수인계 성격 문서
- `02_한글화_작업`: 롬/파일 분석, 추출·재삽입, 폰트/UI/대사, 빌더, 중간 분석·staging
- `03_검수_프로그램`: 게임 전용 원장, 카테고리화, 검수 프로그램, 최종 CSV 반입
- `04_최종_배포`: 최종 모드·패치·패처·배포 준비 산출물
- `05_HD Pack`: 폴더만 기본 생성. 사용자가 명시적으로 요청하기 전 실제 HD Pack 작업 금지
- `버그 리포트`: 재현된 오류, 실플레이 문제, 증거와 추적 기록

프로젝트 폴더를 만들기 전에 바탕화면, 사용자 홈, 다른 게임 프로젝트, 공용 임시 작업장에 게임별 작업물을 흩뿌리지 않는다.

`.github`, `docs`, `source`, `staging`, `tests`, `tools`, `work`, `셀프 검수 프로그램`, `인수인계`, `작업 자료` 등은 특정 프로젝트에서 필요하면 추가할 수 있지만 신규 프로젝트의 공통 필수 6폴더로 간주하지 않는다.

## 2. 초기 기술 분석과 최소 한글 출력

롬/게임 파일을 받으면 먼저 구조를 분석한다.

확인 대상:

- 텍스트 저장 위치와 형식
- 추출·재삽입 가능 여부
- 인코딩
- 폰트 구조
- 원문 재삽입 시 동작 보존 여부
- 최소 빌더/패처 경로
- 가장 작은 한글 샘플 삽입 가능 여부

아직 전체 대사를 번역하지 않는다.

최소 한글 출력 샘플을 만든 뒤 사용자가 실제 게임에서 한 글자 또는 짧은 문장의 표시를 확인한다.

---

## 3. 대량 번역 전 기술 안전성 게이트

최소 한글 출력 성공 후 `workflow/EARLY-TEXT-RUNTIME-GATE.md`를 적용한다.

반드시 검증할 항목:

- 대사창별 가로 최대 픽셀 폭
- 조건별 안전 표시량
- 최대 줄 수
- 자동 줄바꿈 여부
- `[n]` 유지
- `[n]` 삭제
- `[n]` 이동
- `[n]` 추가
- `[n]` 개수 변경
- 반각/전각 영문·숫자·문장부호·공백
- 게임 인코딩/RSC/레코드 구조
- 다음 대사 진행
- 선택지 진행
- 다음 장면 전환
- 음성·대기·연출·분기

`[n]`은 동작별로 PASS / FAIL / UNTESTED를 따로 기록한다. 하나가 성공했다고 다른 동작을 허용하지 않는다.

표시 성공과 진행 성공을 별도로 판정한다.

결과는 다음 셋 중 하나로 기록한다.

```text
진행 가능
조건부 진행
기술 보강 후 재판정
```

안전한 경로를 확보하지 못하면 대량 번역을 시작하지 않는다.

---

## 4. 전체 일본어 원문 추출과 안정 원장

기술 안전성 게이트 통과 후 일본어 원문 전체를 추출한다.

단순 문장 목록이 아니라 검수 프로그램에서 장기적으로 사용할 안정 원장으로 만든다.

최소 권장 필드:

```text
row_key
source_file_or_table
source_index
japanese_source
speaker
listener
category
subcategory
control_tokens
current_translation
status
notes
```

`row_key`는 번역문이 바뀌어도 흔들리지 않는 안정 ID여야 한다.

카테고리화의 목적은 웹 ChatGPT가 문자열의 기능을 구분한 상태에서 번역/검수하도록 만드는 것이다.

## 6. 게임 전용 검수 프로그램 선행 구축

용어집을 최종화하기 전에 전체 원장과 카테고리를 다룰 수 있는 게임 전용 검수 프로그램을 먼저 준비한다.

기본 베이스 참고:

```text
D:\Codex\# 검수 프로그램\EVE 고스트 에너미즈
```

카테고리/세부분류 참고:

```text
D:\Codex\# 검수 프로그램\이상한 환상향 로터스 라비린스
```

재사용 가능한 프로그램 구조와 기능만 참고한다. EVE/로터스의 게임별 데이터, 용어, 관계, 오프셋, 확정 번역은 새 게임에 섞지 않는다.

검수 프로그램은 최소한 다음을 지원하는 방향으로 구축한다.

- 안정 원장 로딩
- `row_key` 기반 추적
- category/subcategory 필터
- 검색
- 수정 이력
- 사용자 실플레이 확정값 관리
- 최종 누적 CSV 반입
- 모드/패치 생성 경로와 연결

게임마다 전용 검수 프로그램을 별도로 운영한다.

---

## 7. 번역 전 0단계 기준자료

전체 원장과 카테고리, 검수 프로그램이 준비된 뒤 언어 기준자료를 만든다.

필수 대상:

- 캐릭터 이름·별칭·칭호
- 세계관 용어
- 장소·던전·조직·종족
- 아이템·스킬·시스템 용어
- 캐릭터 성격
- 기본 말투
- 1인칭/2인칭
- 화자 → 청자 방향 관계
- 방향별 반말/존댓말
- 방향별 호칭
- 관계 변화 시점
- 예외
- 근거 출처
- confirmed / provisional / HOLD 상태

관계는 반드시 방향별로 관리한다.

```text
A → B : 반말
B → A : 존댓말
```

같은 비대칭 관계를 정상적으로 표현할 수 있어야 한다. `서로 반말` 같은 대칭 가정을 기본값으로 두지 않는다.

일본어 원문이 authority이며 영어판은 의미·문맥·철자 보조 자료로만 사용한다.

## 8. Google Drive 검수 작업장

Google Drive의 PC 동기화 상위 루트는 다음이다.

```text
F:\내 드라이브\검수 프로그램
```

게임별 실제 작업공간은 다음 구조를 기본으로 한다.

```text
F:\내 드라이브\검수 프로그램\<게임명>\
├─ 01_최신_용어집
├─ 02_검수_필수파일
└─ 03_검수_수정_CSV
```

이 구조의 목적은 PC를 켜두지 않아도 휴대폰/웹 ChatGPT에서 검수 작업을 계속할 수 있게 하는 것이다.

기존 게임별 Drive 구조가 있으면 중복 폴더를 만들거나 억지로 재배치하지 않고 동일 역할의 기존 폴더를 사용한다.

### 8.1 `01_최신_용어집`

최신 용어 기준을 둔다.

- 캐릭터명
- 세계관 용어
- 아이템/스킬/시스템/던전명
- 카테고리별 용어집
- confirmed / provisional / HOLD 상태

### 8.2 `02_검수_필수파일`

휴대폰의 웹 ChatGPT만으로도 검수할 수 있도록 다음을 준비한다.

- 번역 전 기준자료
- 캐릭터 성격/말투
- 방향별 관계도
- 반말/존댓말/호칭
- HOLD
- 출처
- `layout_profile` 또는 동등 출력/진행 규격
- `[n]`, 반각/전각, 가로폭, 최대 줄 수, RSC 보호 규칙
- 1차 1,000행 전용 지시문
- 2차 1,000행 전용 지시문
- 3차 500행 전용 지시문

1차·2차·3차 지시문은 물리적으로 분리하며 서로 섞지 않는다.

### 8.3 `03_검수_수정_CSV`

검수 프로그램 원장에서 내보낸 검수용 CSV를 둔다.

최소 유지 필드:

```text
row_key
japanese_source
category
subcategory
speaker
listener
control_tokens
current_translation
review_status
```

단순 일본어 문장 덤프를 검수용 대사집으로 사용하지 않는다.

## 9. Google Drive 등록은 1차 검수 전 하드 게이트

로컬 `work`나 `03_검수_프로그램`의 자료는 조사·초안·검증용 staging이다.

다음이 끝나기 전에는 1차 1,000행 검수를 시작하지 않는다.

1. 게임별 Google Drive 작업공간 확인
2. `01_최신_용어집` 최신화
3. `02_검수_필수파일` 최신화
4. `03_검수_수정_CSV`에 분류된 원장 CSV 준비
5. Drive 동기화 확인
6. 등록한 파일을 다시 읽어 실제 반영 확인

Drive 등록 전 상태를 `0단계 완료`라고 보고하지 않는다. 필요하면 `LOCAL_DRAFT_ONLY` 또는 `DRIVE_REGISTRATION_PENDING`으로 표현한다.

Drive 접근이 불가능하면 로컬 파일만으로 정상 완료 처리하지 않는다.

---

## 10. 웹 ChatGPT 3단계 검수

Google Drive 작업공간이 준비된 뒤 웹 ChatGPT에서 검수한다.

```text
1차: 전체 대사집을 1,000행 단위로 기초 검수
→ 2차: 1차 결과 전체를 다시 1,000행 단위로 자연화·말투 검수
→ 3차: 2차 결과 전체를 다시 500행 단위로 최종 정밀검수
```

각 차수는 다른 구간을 맡는 것이 아니라 전체 대사집을 다시 훑는 별도 패스다.

---

## 11. 최종 누적 CSV 반입과 실기 검수

3차 완료 후 Google Drive에서 받는 핵심 전달물은 다음 형식이다.

```text
<게임약칭>_최종대사_수정_누적.csv
```

예:

```text
LLR_최종대사_수정_누적.csv
```

이 파일을 게임 전용 검수 프로그램의 최신 원장에 반입한다.

그 뒤:

```text
최종 누적 CSV 반입
→ 정적 검증
→ 모드/패치 생성
→ 실제 게임 테스트
→ 사용자 실플레이 확정 수정
→ 원장에 최우선 확정값으로 재반영
```

Drive의 중간 파일 전체를 Codex 프로젝트로 다시 복사할 필요는 없다. 최종 누적 CSV가 로컬 검수 프로그램으로 돌아오는 핵심 전달물이다.

---

## 12. 기존 프로젝트 적용

기존 프로젝트는 현재 루트와 기존 성공 자산을 보존한다.

- 폴더명을 새 기본 구조에 맞추기 위해 강제 이동/이름 변경하지 않는다.
- 이미 검증된 추출기, 빌더, 패처, 폰트, 원장, 실플레이 확정값을 근거 없이 재설계하지 않는다.
- 현재 프로젝트에 빠진 단계만 보강한다.
- 기존 Google Drive 구조가 있으면 그대로 연결한다.
- `05_HD Pack`은 사용자 요청 없이 작업하지 않는다.

## 13. 문서 변경 범위

이 설계를 반영할 때 최소한 다음 문서를 함께 정합화한다.

- `CODEX-LOCALIZATION-BOOTSTRAP.md`: 전체 대순서와 하드 게이트
- `workflow/PROJECT-OPERATING-MODEL.md`: 기본 6폴더, 검수 프로그램, Drive 역할
- `review/PRE-TRANSLATION-SETUP.md`: 0단계 전에 전체 원장/카테고리/검수 프로그램 선행 조건
- `templates/AGENTS.template.md`: 프로젝트 단계, 기본 폴더, Drive/검수 프로그램 연결

`workflow/EARLY-TEXT-RUNTIME-GATE.md`의 기존 안전성 원칙은 유지하고 전체 라이프사이클 안의 위치만 명확하게 연결한다.

필요하면 기존 Google Drive 관련 문구에서 `권장 구조`라는 표현을 제거하고, 실제 운영 구조와 완료 조건을 명시한다.

## 14. 최종 라이프사이클

```text
신규 프로젝트 6폴더 생성
→ 롬/게임 구조 분석
→ 최소 한글 출력
→ 사용자 실기 확인
→ 가로폭·줄 수·[n]·반각/전각·진행 안전성 게이트
→ 전체 일본어 원문 추출
→ 안정 row_key 부여
→ 카테고리·세부 카테고리 분류
→ 게임 전용 검수 프로그램 구축
→ 번역 전 0단계 기준자료 구축
→ Google Drive 01_최신_용어집 / 02_검수_필수파일 / 03_검수_수정_CSV 준비
→ 휴대폰/웹 ChatGPT 1차 1,000행
```
