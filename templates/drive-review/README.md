# Google Drive 공통 검수 양식

Codex와 GPT가 같은 순서로 이어서 작업하기 위한 양식이다. 게임별 지시문과 빈 CSV 자체를 이 저장소에서 받을 수 있다. 기존 로컬 예시가 없어도 세팅할 수 있다.

## 세팅

로컬 프로젝트를 처음 만들 때 `03_검수_자료` 아래 `00_일본어 추출` → `01_1차 검수 준비` → `02_3차 검수 완료` → `04_검수 프로그램`을 순서대로 만든다. `01_1차 검수 준비` 아래에는 `01_캐릭터` → `02_스킬` → `03_아이템` → `04_시스템` → `05_대사`를 미리 만든다. 7번의 일본어·영어 전체 추출·백업은 `00_일본어 추출`, 8번의 원장과 카테고리별 500행 CSV는 `01_1차 검수 준비`에 저장한다. CSV는 `01_1차 검수 준비/01_캐릭터/캐릭터_0001-0500.csv`처럼 해당 카테고리 폴더에 넣는다.

`02_3차 검수 완료`는 처음에는 빈 폴더로 만든다. 폴더가 있다는 이유로 검수 완료로 표시하지 않는다. 3차 전체 검수 후 Drive 최종 CSV·병합 원장·확정 용어/인물/관계·사용한 지시문을 `03_검수_자료/02_3차 검수 완료`에 보관한다. 가져온 자료의 Drive 폴더 구분과 카테고리·파일명은 유지하고 기존 입력·성공 자료를 덮어쓰지 않는다.

`04_검수 프로그램` 폴더도 처음부터 빈 폴더로 만든다. 실제 검수 프로그램의 소스·실행 파일·설정은 `03_검수_자료/04_검수 프로그램`에 보관하고, 프로그램은 `02_3차 검수 완료`의 최신 병합 원장을 불러오도록 연결한다. 폴더 생성만으로 프로그램 제작·검증 완료를 표시하지 않는다.

Drive에는 번역 대상 원장을 `00_전체원장`에, 준비한 카테고리 폴더와 분할 CSV를 `03_1차_검수_CSV`에 올린다. 로컬 준비 폴더와 Drive 검수 차수 폴더는 이 대응으로 연결한다.

1. 아래 구조로 게임별 Drive 폴더를 만든다.
2. [공통 작업 지시문](../PROJECT-INSTRUCTIONS.md)은 `공통작업지시문.md`, [최신 부트스트랩](../../CODEX-LOCALIZATION-BOOTSTRAP.md)은 `작업순서.md`로 본문을 복사한다. [진행상태 양식](../진행상태.template.md)도 올린다.
3. 이 폴더의 Markdown·CSV 양식을 아래 위치로 복사한다. 게임정보.md를 해당 게임의 실제 규격과 **Drive 파일 링크**로 채운다. 시작하기.md에도 공통 지시문·작업순서·진행상태·게임정보·진행표의 실제 링크를 적는다.
4. 7번에서 ROM의 일본어·영어 원문을 모두 추출해 별도로 백업한다. 8번에서 게임 화면에 표시되는 번역 대상만 카테고리화·스토리 순서 정렬해 `00_전체원장`에 보존한다. 화면에 나오지 않는 파일명·디버그·라이브러리 문자열은 원장·검수 CSV에서 제외하고 원문·언어·원본 위치·제외 근거를 별도로 백업한다. 출력 여부가 불확실하면 확인 필요 목록에 남긴다. 원문 언어와 고정 `row_key`를 유지한 **카테고리별 최대 500행 CSV**를 `03_1차_검수_CSV`에 올린다. 마지막 묶음은 남은 행만 넣는다. 차수별 출력 폴더는 비워둔다.
5. 올린 파일을 다시 읽어 내용·행 수·링크·읽기/쓰기 권한을 확인한다. 완료 전에는 검수 환경 준비 완료로 표시하지 않는다.

## 폴더

```text
<게임명>/
├─ 시작하기.md
├─ 공통작업지시문.md
├─ 작업순서.md
├─ 진행상태.md
├─ 00_전체원장/
├─ 01_최신_용어집/
│  ├─ 용어집.csv
│  ├─ 캐릭터.csv
│  ├─ 관계_말투.csv
│  ├─ 사용자_확정값.csv
│  ├─ 후보/                 # 파일별 새 용어·인물·관계 제안
│  └─ 3차_확정기준/        # 2차 종료 후 정리한 최종 검수 기준
├─ 02_검수_지시문/
│  ├─ 공통규칙.md
│  ├─ 1차.md
│  ├─ 2차.md
│  ├─ 3차.md
│  ├─ 게임정보.md
│  ├─ 출력규격.md
│  └─ 진행표.csv
├─ 03_1차_검수_CSV/
├─ 04_2차_검수_CSV/
├─ 05_3차_검수_CSV/
├─ 06_3차_완성본_CSV/
└─ 07_영문판_참고자료/      # 같은 게임의 영어판 자료가 있을 때
```

각 차수의 대분류는 **캐릭터 / 아이템 / 스킬 / 시스템 / 대사** 5개다. 캐릭터는 이름, 아이템·스킬은 이름과 설명, 시스템은 메뉴·메시지·튜토리얼, 대사는 스토리 대사를 하위 분류로 기록한다. 장비는 아이템에 포함하고 도감 등 추가 종류는 실제 내용에 맞는 하위 분류로 기록한다. 항목이 없는 분류는 빈 검수 파일을 만들지 않는다. `후보.csv`는 `후보/후보_<담당파일명>.csv`로 복사한다.

카테고리 폴더는 `01_캐릭터`, `02_스킬`, `03_아이템`, `04_시스템`, `05_대사`로 미리 만든다. 카테고리마다 500개씩 나누며 `01_캐릭터/캐릭터_0001-0500.csv`, `01_캐릭터/캐릭터_0501-1000.csv`, `03_아이템/아이템_0001-0500.csv`처럼 저장한다. 폴더 번호는 정렬용이며 `category` 값은 캐릭터·스킬·아이템·시스템·대사로 유지한다. 범위 숫자는 그 카테고리의 분할 순번이며 `row_key`를 다시 매기는 번호가 아니다. 다른 대분류를 한 파일에 섞지 않는다.

## 검수 순서

| 차수 | 입력 | 출력 | 할 일 |
|---|---|---|---|
| [1차](1차.md) | 03_1차_검수_CSV | 04_2차_검수_CSV | 원문에 충실한 번역, 캐릭터 이름·스킬명·아이템명·시스템 메시지의 타 작품 통용 표현·출처 확인, 이름·반복 고유명사 기록, 확실한 화자 입력 |
| [2차](2차.md) | 04_2차_검수_CSV | 05_3차_검수_CSV | 원문·1차본·앞뒤 각각 2~3문장 대조, 화자·용어집·고유명사집·관계도·성격/말투 기준 완성, 명백한 오역과 존대·반존대·반말·독백 오류 수정 |
| [3차](3차.md) | 05_3차_검수_CSV | 06_3차_완성본_CSV | 원문부터 모든 행을 다시 번역해 2차본과 비교, 1·2차 오류 수정, 이름·스킬명·아이템명·시스템 메시지의 통용 표현 재확인, 출력 규격 반영 |

같은 카테고리·파일명으로 다음 폴더에 전체 결과를 저장한다. 각 차수 전체 처리와 보류 기록 후 다음 차수로 간다. 2차에서는 원문·1차본·문맥 대조로 기준 자료를 완성하고 명백한 오역·누락과 존대·반존대·반말·독백 오류를 수정하고, 3차에서는 원문을 독립적으로 다시 번역해 비교한다. 3차 확정 기준이 준비되지 않았다면 먼저 2차 통합을 확인한다. 2차 종료 후 정리한 용어·캐릭터·관계 자료를 `3차_확정기준`에 복사하고 미확정 후보는 따로 둔다. 3차 종료 후 10번에서 미추출·미번역 누락을 재점검하고 새 항목의 9번 검수를 마친 뒤, 11번에서 **`row_key`로 전체 원장에 결과를 매칭해 하나의 파일로 병합**한다. 보존한 순서를 복원하고 키 누락·중복·알 수 없는 키를 확인한다. 문맥 참고 문장은 추가 원장 행으로 합치지 않는다.

타 작품의 통용 표현 확인은 **1차와 3차**에서 한다. 2차에는 이 확인 작업을 추가하지 않는다. 3차는 모든 행을 원문부터 다시 번역해 검증하며, 2차 완료 표시만으로 통과시키지 않는다.

출력 제한은 해당 게임의 화면·문자열 종류·행별 검증값을 사용한다. 시험 대사 한 행의 줄 수·칸 수·바이트 수를 다른 화면이나 모든 행에 일괄 적용하지 않는다. RSC는 실제 저장 인코딩과 원문·제어 구조에 따라 계산하며, 공백·줄바꿈·종료 문자 정책도 검증된 조건만 적용한다. 문자 매핑·지원 글자·행별 예산이 없으면 삽입 적합성은 기술 확인 보류로 남긴다. 게임별 검증값은 [출력규격.md](출력규격.md)에 적는다.

## CSV 입력 규칙

- [검수.csv](검수.csv)는 **새 프로그램용 최소 예시**다. 기존 게임 CSV의 열 이름·ID·보호 열을 바꾸지 않고 [게임정보.md](게임정보.md)에 실제 열 대응을 적는다. 스토리 순서·장면·분기·제품별 필요한 열은 원장에 보존한다.
- CSV는 UTF-8이며 따옴표와 줄바꿈을 포함한 논리 데이터 행으로 **카테고리별 최대 500개씩** 나눈다. 헤더는 제외하고 읽기 전용 문맥은 별도 열에 넣는다. 단순 텍스트 줄 수로 자르지 않는다.
- `row_key`는 전체 원장에서 유일하고 원본 위치와 연결된 보호 값이다. 분할·검수·병합 중 변경·재발급하지 않는다. 같은 문구라도 다른 원본 위치의 키는 구분한다.
- 용어집은 확정 / 후보 / 보류를 구분한다. 사용자 직접 확정값은 사용자_확정값.csv에 따로 남긴다. 전체 / 특정 장면 / 특정 의미 등 적용 범위를 기록한다.
- 검수 상태값은 기존 프로그램의 허용값을 게임정보에 적는다. 새 프로그램은 미검수 / 1차 완료 / 2차 완료 / 3차 완료 / 보류를 사용할 수 있다.
- 대사 원장과 검수 파일은 실제 스토리 진행 순서로 기록한다. 같은 장면·분기의 앞뒤 2~4문장을 읽기 전용 문맥으로 제공한다. 파일 경계에서도 원장·인접 파일을 참조하며 다른 분기 대사를 이어 붙이지 않는다. 전체 게임의 반복 고유명사를 확인할 수 있게 원장 링크도 제공한다.
- 모르는 출력 조건은 미확인으로 남긴다. 다른 게임의 줄 수·폭·RSC·줄바꿈을 복사하지 않는다.
- Drive에는 해당 게임 자료를 넣는다. 공개 GitHub에는 공통 지시문과 빈 양식만 보관한다.

실제 작업은 [공통규칙](공통규칙.md)과 해당 차수 지시문을 모두 읽고 수행한다. 언어 검수 완료와 실제 게임 실행 검증 완료는 구분한다.


## 파일별 중간보고와 연속 진행

CSV 1파일(헤더 제외 최대 500행)을 마칠 때마다 결과 저장·재확인·진행표 갱신 후 처리 파일명·행 수·수정/보류 사항·다음 파일을 **중간보고로 남기고, 사용자 응답을 기다리지 않고 승인된 같은 차수의 다음 파일로 즉시 진행한다.** 보고는 작업 중단이나 다음 파일별 재승인 요청이 아니다. 사용자가 1파일만 지정했으면 임의로 범위를 늘리지 않으며, 입력 누락·저장 실패·사용자 판단이 필요한 충돌 등 실제 장애만 이유를 기록하고 확인한다. 차수 전체 종료 후 기준 자료를 통합한 다음 다음 차수로 넘어간다.
