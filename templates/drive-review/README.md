# Google Drive 공통 한글화 검수 양식

모든 **신규 게임**의 기본 경로는 **1차 용어 선확정 → 2차 원문 기반 본번역 → 2차 전체 기준 통합 → 3차 원문 독립 재검수**다. 1차 대사 초벌·1차 대사 검수는 수행하지 않는다. 이 문서는 Codex와 Claude 모두에 적용할 공통 템플릿이다. 기존 진행 프로젝트의 폴더·진행 상태는 승인 없이 자동 변경하지 않는다.

## 핵심 원칙

- **1차는 검수용 CSV를 생성하지 않는다.** 캐릭터 이름·별칭·칭호, 아이템·장비, 스킬·능력, 시스템·UI·전투 용어, 장소·조직·세계관 등 고유명사를 원문·출처로 확인하고 **5종 확정 용어집**에 기록한다. 설명·대사 등 문장 전체를 초벌 번역하지 않는다.
- **2차가 첫 대사 본번역이다.** 원문·같은 분기 문맥을 먼저 읽어 정확한 한국어를 작성한다. 기존 번역이 있어도 이를 정답으로 삼지 않는다. 동시에 캐릭터 성격·말투 및 화자→청자 관계를 근거와 함께 수집한다.
- **2차 전체 완료 후 통합 단계**에서 관계·호칭·시점별 변화와 용어 충돌을 정리하고 `3차_확정기준`을 버전 고정한다. 그 전에는 3차를 시작하지 않는다.
- **3차는 전 행 독립 재검수**다. 원문부터 다시 의미·화자·청자를 판단하고 2차본과 대조하여 오역·누락을 수정하고 표현과 말투를 완성한다.
- 확정 용어와 사용자 확정값은 승인 없이 바꾸지 않는다. 출력 폭·줄 수·저장 인코딩·RSC는 해당 게임에서 검증한 규격만 적용한다.

## 신규 프로젝트의 로컬 준비

`03_검수_자료`에는 다음을 준비한다. 기존 `01_1차 검수 준비`라는 이름 대신 **`01_원문·2차 준비`**를 사용한다.

```text
03_검수_자료/
├─ 00_일본어 추출/          # 일본어·영어 전체 원문 및 제외 근거 백업
├─ 01_원문·2차 준비/       # 전체 원장과 2차 입력용 최대 500논리행 CSV
│  ├─ 01_캐릭터/
│  ├─ 02_스킬/
│  ├─ 03_아이템/
│  ├─ 04_시스템/
│  └─ 05_대사/
├─ 02_3차 검수 완료/       # 3차 전체 종료 후 결과 복사; 초기에는 빈 폴더
└─ 04_검수 프로그램/       # 실제 검수 프로그램 자료; 초기에는 빈 폴더
```

7번에서 전체 원문과 제외 대상을 `00_일본어 추출`에 백업한다. 8번에서 **게임 화면에 표시되는 번역 대상**을 원본 위치·원문 언어·고정 `row_key`와 함께 `01_원문·2차 준비`의 원장과 카테고리별 분할 CSV로 정리한다. 화면 노출 여부가 불명확하면 추정 완료 처리하지 않는다. 로컬 2차 입력 사본을 Drive의 `03_2차_원문_CSV`에 올린다. **`1차 검수 준비`나 `1차_검수_CSV`는 새로 만들지 않는다.**

3차 전체 완료 후 Drive 최종 CSV·병합 원장·확정 용어/캐릭터/관계·사용한 지시문을 로컬 `02_3차 검수 완료`에 보관한다. 검수 프로그램은 `04_검수 프로그램`에 만들고 완료된 병합 원장을 사용한다. 폴더만 만들었다고 검수·프로그램 제작·실기 검증이 완료된 것은 아니다.

## 신규 게임의 Google Drive 구조

```text
<게임명>/
├─ 시작하기.md
├─ 공통작업지시문.md
├─ 작업순서.md
├─ 진행상태.md
├─ 00_전체원장/
├─ 01_최신_용어집/
│  ├─ 캐릭터_확정용어집.csv
│  ├─ 아이템_확정용어집.csv
│  ├─ 스킬_확정용어집.csv
│  ├─ 시스템_확정용어집.csv
│  ├─ 고유명사_확정용어집.csv
│  ├─ 캐릭터.csv                  # 성격·일인칭·말투 근거
│  ├─ 관계_말투.csv               # 화자→청자·시점·장면별 규칙
│  ├─ 사용자_확정값.csv
│  ├─ 후보/                       # 미확정·충돌 후보와 출처
│  └─ 3차_확정기준/              # 2차 전체 통합 후 생성
├─ 02_검수_지시문/
│  ├─ 공통규칙.md
│  ├─ 1차.md                     # 용어 선확정 지시문, 대사 번역 아님
│  ├─ 2차.md                     # 원문 기반 최초 본번역
│  ├─ 3차.md                     # 독립 재검수 및 완성
│  ├─ 게임정보.md
│  ├─ 출력규격.md
│  └─ 진행표.csv
├─ 03_2차_원문_CSV/             # 2차 입력: 1차 초벌 없는 원문 CSV
├─ 04_3차_검수_CSV/             # 2차 출력 = 3차 입력
├─ 05_3차_완성본_CSV/           # 3차 출력
└─ 06_영문판_참고자료/          # 해당 게임의 대조 자료가 있을 때
```

`03_2차_원문_CSV`·`04_3차_검수_CSV`·`05_3차_완성본_CSV`에는 대상 카테고리에 한해 `01_캐릭터`, `02_스킬`, `03_아이템`, `04_시스템`, `05_대사` 하위 폴더를 둔다. **1차 대사 검수 폴더는 없다.** 카테고리 번호는 정렬용이고 `category` 값과 `row_key`는 변경하지 않는다. 이름/설명/스토리 등은 `subcategory`로 구분한다. 장비는 아이템에 포함할 수 있고 도감 등은 실제 원장 분류에 따른다. 없는 카테고리에 빈 데이터 CSV를 생성하지 않는다.

## 초기 세팅

1. [공통 작업 지시문](../PROJECT-INSTRUCTIONS.md)을 `공통작업지시문.md`로, [Codex 부트스트랩](../../CODEX-LOCALIZATION-BOOTSTRAP.md) 또는 [Claude 부트스트랩](../../CLAUDE-LOCALIZATION-BOOTSTRAP.md)의 **선택한 역할별 최신 본문**을 `작업순서.md`로 복사한다. [진행상태 양식](../진행상태.template.md)도 올린다.
2. [게임정보.md](게임정보.md)에 실제 원장·출력규격·분할 파일·용어집·관계 기준·사용자 확정값·진행표의 Drive 링크와 수정/보호 열을 기록한다. [시작하기.md](시작하기.md)에 실제 링크를 적는다.
3. 7번 전체 추출 및 8번 카테고리별 분할을 마치고 `00_전체원장`과 `03_2차_원문_CSV`에 원문 CSV를 준비한다. 헤더 제외 최대 **500논리행/파일**로 자르며 마지막 파일은 남은 행만 둔다. `row_key`를 임의 발급·재발급하지 않는다.
4. `02_검수_지시문/1차.md`에 따라 5종 용어집을 **대사 본번역 전에 선확정**한다. [용어집.csv](용어집.csv)를 5개 확정 용어집의 초기 헤더 양식으로 복사해 사용할 수 있다. [캐릭터.csv](캐릭터.csv)·[관계_말투.csv](관계_말투.csv)·[사용자_확정값.csv](사용자_확정값.csv)도 필요한 위치에 복사한다. 고유명사는 단 한 번 나타나도 후보로 수집하고, 동일 여부·근거·승인을 확인해 확정한다. 미확정값은 확정파일에 섞지 않는다.
5. 데이터·링크·원문·행 수·권한·5종 용어 확정/동결 상태를 다시 확인한다. 준비되지 않은 상태를 완료로 표시하지 않는다. 2차 출력·3차 출력 폴더는 처음에 비워 둔다.

## 차수별 입력·출력과 역할

| 단계 | 입력 | 출력 | 수행 |
|---|---|---|---|
| [1차](1차.md) 용어 선확정 | `00_전체원장`, 원문, 2차 입력 CSV의 읽기 전용 자료 | `01_최신_용어집`의 5종 확정 용어집과 증거/보류 기록 | 캐릭터·아이템·스킬·시스템·고유명사 확정. **대사 초벌·1차 검수 CSV 생성 없음** |
| [2차](2차.md) 본번역 | `03_2차_원문_CSV` | `04_3차_검수_CSV` | 원문에서 최초 본번역, 화자·청자·성격·말투·관계 근거 수집 |
| 통합 게이트 | 2차 모든 결과·팀별 근거 | `01_최신_용어집/3차_확정기준` | 캐릭터·관계·말투·시점별 변화 통합, 충돌 해결, 기준 버전 고정 |
| [3차](3차.md) 독립 재검수 | `04_3차_검수_CSV`와 확정기준 | `05_3차_완성본_CSV` | 모든 행 원문 독립 재확인, 오역 수정, 자연화·최종 통일 |

5종 용어집의 **이름·단어·고정 용어**를 1차에 확정하며, 문장 형태의 스킬·아이템 설명/시스템 문구와 스토리 대사 중 아직 승인되지 않은 번역문은 **2차·3차에서 원문 기반으로 번역·검수**한다. 원문 문장의 정확성 평가와 용어 표기 확정은 별개다. 사전 승인된 완성 문장이라도 실제 맥락과 일치하는지 검토한다.

## CSV·문맥·출력 보호 규칙

- [검수.csv](검수.csv)는 최소 예시다. 기존 게임의 CSV 열 이름·원본 키·보호 열·제어 구조는 변경하지 않는다. [게임정보.md](게임정보.md)에 실제 대응을 기록한다.
- 일본어·영어 원문은 `source_language` 등 원장의 실제 기록을 따르며, 영어판이나 다른 게임의 용어는 **확인된 대응**에 한해 보조 자료로 삼는다. 다른 작품의 표기를 자동 이식하지 않는다.
- 대사와 검수 파일은 확인된 스토리 순서를 유지한다. 같은 장면·분기의 앞뒤 2~4문장을 읽기 전용으로 참조하고, 다른 분기·미확정 경로를 무리하게 이어 붙이지 않는다. 문맥 참조 문장은 원장 데이터 행에 추가하지 않는다.
- 새 게임은 대사 `review_status`를 **2차 완료 / 3차 완료 / 보류 등 해당 스키마에서 허용된 값**으로만 기록한다. 1차 용어 선확정은 별도 진행 게이트이므로 대사를 `1차 완료`로 일괄 표시하지 않는다. 기존 프로그램의 상태값을 멋대로 삭제·변경하지 않는다.
- 사용자 직접 확정값은 별도 파일로 보호한다. 선확정 용어는 작업자가 임의 변경하지 않고 원문·영향 `row_key`·근거를 갖춘 변경 후보로 총괄에게 보고한다.
- 화면 폭·표시 줄·문자 매핑·줄바꿈·저장 인코딩·RSC 등의 제한은 **게임·화면·문자열 종류별 실제 검증값**만 사용한다. 기술 검증이 안 된 문구는 의미를 생략하지 않고 기술 보류로 남긴다.
- 각 파일은 전체 행을 저장·재개방한 뒤 원문·고유 키·행 수·순서·토큰·보호 열과 미해결 항목을 검사한다. 3차 전체 종료 후 신규 누락을 찾고 필요한 2→3차 검수를 거쳐 **`row_key`로 원장에 최종 병합**한다.
- **언어 검수 완료는 ROM 삽입·픽셀·실제 게임 진행 검증 완료가 아니다.** 결과·진행표에는 두 상태를 구분해 표시한다.

## 파일별 중간보고와 연속 진행

2차·3차에서는 CSV 1파일(헤더 제외 최대 500행)을 마칠 때마다 결과 저장·재개방 검증·진행표 갱신 후 처리 파일명·행 수·오역/보류·다음 파일을 보고한다. 승인된 같은 차수의 다음 파일은 파일별 재승인 없이 진행하되, 사용자가 1파일만 지정했다면 범위를 늘리지 않는다. **1차는 대사 CSV 파일 단위 완료가 아니라 5종 용어집 확정과 증거·보류·동결 상태를 보고한다.** 실제 장애나 승인 충돌은 근거와 함께 보고한다.
