# 4차: 줄바꿈·출력 배치와 미번역 누락 최종 확인

3차에서 완성한 의미·말투를 유지하면서 **줄을 최대한 활용하는 배치, 빈 번역란, 번역문에 남은 일본어**를 확인한다. 대사 전체를 다시 번역하는 차수가 아니다. 실제로 문제가 있는 행만 수정한다.

## 시작 조건·입출력

- 입력: 3차가 저장·재개방한 `05_4차_검수_CSV/<카테고리>/<파일명>.csv`와 해당 게임의 원장·출력규격·확정 용어/관계·사용자 확정값.
- 출력: `06_검수완료/<같은카테고리>/<같은파일명>.csv`. 전체 행을 유지한다. 영문판 대조가 필요하고 실제 대응 자료가 있을 때만 `07_영문판_참고자료`를 참고한다.
- 지정 CSV 1파일의 헤더 제외 최대 500논리행을 처리한다. 게임정보에 적힌 실제 번역 열과 수정 허용 열만 사용하고 원문·row_key·순서·원본 위치·보호 열은 변경하지 않는다.
- 폭·줄 수·폰트·줄바꿈 토큰은 게임·화면 종류별 검증값만 쓴다. 확인된 값과 기존 도구를 재사용하고 별도 검수 프로그램 제작이나 전체 실기 재검증을 요구하지 않는다.

## 줄바꿈 기준

1. 의미와 어절을 보존하면서 **각 줄을 가능한 한 채운다.** 남는 공간을 줄이려고 어절 중간을 끊거나 번역문을 불필요하게 줄이지 않는다. 자동 줄바꿈으로 어절이 쪼개지는 경우에도 허용된 배치 방법으로 조정한다.
2. 금지 예시에서 `/`는 화면상 줄 경계를 뜻한다: `그/래서`, `이렇게/라도 널 잡고 싶었어`. `그래서`, `이렇게라도`는 각각 한 어절이므로 나누지 않는다. 서로 다른 어절의 공백 경계에서 나누는 것은 가능하다.
3. **마침표·느낌표·물음표로 끝난 문장 뒤에서는**, 줄에 여유가 있어도 읽기 좋게 줄바꿈할 수 있다. 단, 남은 문장과 변수 치환까지 실제 폭으로 배치했을 때 전체 최대 줄 수를 넘지 않아야 한다. 인용문은 문장 종결 뒤 닫는 따옴표와 함께 처리한다.
4. 예를 들어 최대 3줄인 창에서 1번째 또는 2번째 줄의 문장 끝에서 일찍 줄을 바꿔도, 나머지가 남은 줄 안에 들어가 총 3줄 이내라면 허용한다. 이 때문에 4줄이 되면 조기 줄바꿈을 조정한다. 3줄은 예시이며 모든 게임에 강제하지 않는다.
5. 실제 출력되는 변수·이름의 확인된 최대 폭, 들여쓰기·패딩·페이지별 줄 수와 명시적/자동 줄바꿈을 함께 계산한다. 긴 어절 하나가 폭을 넘으면 임의로 쪼개거나 용어를 바꾸지 말고 해당 행만 기술 보류로 남긴다.
6. 원문 토큰과 진행에 영향을 주는 보호 명령을 보존한다. `[n]` 이동·삭제·추가·개수 변경은 그 게임에서 허용된 동작만 사용한다. 배치가 예뻐진다는 이유로 보호 구간을 넘겨 옮기거나 페이지 명령을 새로 넣지 않는다.

## 빈 번역란·일본어 잔존 확인

- **번역 대상 행의 번역란이 공란 또는 공백뿐인지 전 행 확인**한다. 빈 값을 완료로 표시하거나 원문 복사·더미 문구로 채우지 않는다. 원문과 문맥이 충분하면 필요한 행만 정확하게 번역하고, 신규/변경 번역은 해당 행에 2차 본번역·3차 독립 검수를 거친 뒤 4차 배치를 확인한다. 이미 정상인 다른 행은 다시 검수하지 않는다.
- 이미 번역된 행 안에 일본어 단어·문장·가나가 남았는지 원문과 대조한다. 가나나 일본어 문장 조각은 후보로 찾되, 한자 하나만으로 일본어 잔존이라고 확정하지 않는다.
- 승인된 원어 표기·의도적 인용·효과음·기능용 문자열·변수·제어 토큰·번역 제외 행은 근거 있는 보존 대상으로 구분한다. 일본어를 무조건 삭제하거나 번역하기 위해 보호 토큰을 바꾸지 않는다.
- 실제 미번역은 관련 row_key에 수정 내용이나 보류 사유를 남긴다. 해결하지 못한 번역 공란·일본어 잔존은 완료로 숨기지 않는다. 근거가 부족한 경우 해당 행만 보류하고 필요한 판단을 보고한다.

## 저장·완료·보고

- 동일 카테고리·파일명으로 전체 CSV를 `06_검수완료`에 저장하고 재개방한다. 행 수·row_key·원문·순서·토큰·보호 열과 줄 수/폭, 공란·잔존 후보의 처리 결과를 함께 확인한다.
- 모든 행의 배치·누락 확인이 끝나고 미해결 문제가 없을 때만 해당 파일의 4차 완료를 기록한다. 보류가 있는 파일도 출력은 보존하되 폴더 이름만으로 완료라고 판단하지 않는다. 스키마에 4차 상태가 없으면 새 열·값을 임의 추가하지 않고 기존 진행표·메모에 차수와 보류를 기록한다.
- 사람에게는 **바뀐 행과 이유, 공란/일본어 잔존 수정·보류, 다음 파일**만 짧게 요약한다. 전체 행을 보고서에 반복 나열하지 않는다. 승인된 같은 차수의 다음 파일은 계속 처리한다.
- 최종 병합은 `06_검수완료`의 채택된 파일을 `row_key`로 연결한다. 신규 누락·수정 행은 필요한 2→3→4차를 거친다. 4차 완료와 실제 게임 삽입·실기 합격은 구분한다.
