# <게임명> 작업 시작하기

Codex와 GPT 모두 먼저 [공통 작업순서](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/CODEX-LOCALIZATION-BOOTSTRAP.md)와 [공통 지시문](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/templates/PROJECT-INSTRUCTIONS.md)을 읽는다. 현재 사용자 지시와 승인 규칙을 우선한다.

게임명이 정해지면 기본 폴더부터 만든다. 사용자에게 `00_원본`과 `09_전용_에뮬` 경로를 안내한다. 원본·포터블 복사는 사용자가 한다. 원본이 없다고 경로를 반복해서 묻거나 폴더 생성을 미루지 않는다.

기본 폴더는 `00_` → `01_` → `02_` → `03_` → `04_` → `05_` → `06_` → `07_` → `08_` → `09_` → `10_` → `11_` → `12_` → `13_` 번호 순서대로 하나씩 생성한다.

처음 준비할 때 `03_검수_자료`을 만든 직후 `00_일본어 추출` → `01_1차 검수 준비` → `02_3차 검수 완료` → `04_검수 프로그램` 하위 폴더도 순서대로 만든다. 7번의 일본어·영어 전체 추출·백업은 첫 폴더, 8번의 원장·카테고리별 500행 CSV는 두 번째 폴더에 저장한다. 분할 CSV는 그 아래 카테고리 폴더별로 보관한다.

`01_1차 검수 준비` 아래에도 `01_캐릭터` → `02_스킬` → `03_아이템` → `04_시스템` → `05_대사`를 처음부터 순서대로 만든다. 각 카테고리의 최대 500행 파일을 해당 폴더에 넣고 `category`와 `row_key`는 유지한다.

`02_3차 검수 완료`는 처음에는 빈 폴더로 만든다. 폴더가 있다는 이유로 검수 완료로 표시하지 않는다. 3차 전체 검수 후 Drive 최종 CSV·병합 원장·확정 용어/인물/관계·사용한 지시문을 `03_검수_자료/02_3차 검수 완료`에 보관한다. 가져온 자료의 Drive 폴더 구분과 카테고리·파일명은 유지하고 기존 입력·성공 자료를 덮어쓰지 않는다.

`04_검수 프로그램` 폴더도 처음부터 빈 폴더로 만든다. 실제 검수 프로그램의 소스·실행 파일·설정은 `03_검수_자료/04_검수 프로그램`에 보관하고, 프로그램은 `02_3차 검수 완료`의 최신 병합 원장을 불러오도록 연결한다. 폴더 생성만으로 프로그램 제작·검증 완료를 표시하지 않는다.

테스트 롬·ISO/CSO·사용자 확인용 빌드는 모두 해당 게임의 `04_테스트 파일`에 저장한다. 최소 한글 출력, 초반 500개 대사, 이미지·동영상 자막, 통합 테스트에도 같은 저장 위치를 사용한다.

테스트 ROM·ISO/CSO를 만들 때는 ISO만 제공하지 않고 **해당 빌드를 바로 부팅하는 실행용 `.cmd`를 같은 테스트 폴더에 함께 만든다.** `09_전용_에뮬`의 실제 실행 파일과 해당 테스트 ROM을 연결하고, 더블클릭하면 에뮬레이터 실행과 게임 부팅까지 이어지도록 게임·에뮬별로 확인한 실행 인자를 사용한다. 공백·한글 경로를 인용하고 파일 존재를 확인하며, 어느 빌드를 실행하는지 파일명·안내에 명시한다. 에뮬만 열리고 게임 선택을 다시 요구하는 실행기는 완료로 보지 않는다. `.cmd` 작성·정적 확인과 실제 부팅 확인은 구분해 기록한다.

폴더 준비 완료를 먼저 보고하고 아래 실제 경로를 안내한다. 원본·포터블은 사용자가 복사한다.

- 원본 등록 위치: `<사용자가 선택한 작업 경로>/<게임명>/00_원본`
- 전체 원문 추출·백업 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/00_일본어 추출`
- 원장·1차 검수 준비 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/01_1차 검수 준비`
- 3차 최종 자료 보관 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/02_3차 검수 완료`
- 테스트 파일 저장 위치: `<사용자가 선택한 작업 경로>/<게임명>/04_테스트 파일`
- 포터블 등록 위치: `<사용자가 선택한 작업 경로>/<게임명>/09_전용_에뮬`
- 진행상태: <현재 단계와 증거를 기록한 파일 링크>
- 게임정보·검증된 출력 규격: <실제 파일 링크>
- 전체 원장: <실제 파일 링크>
- 전용 에뮬: `09_전용_에뮬` — <포터블 복사·설정 분리 상태와 확인 기록>
- 검수 작업공간: <권한에 맞는 링크; 비공개 주소는 공개 저장소에서 제외>
- 기존 성공 자료·사용자 확정값: <실제 파일 링크>

진행상태를 읽고 현재 단계에서 이어서 작업한다. 접근할 수 없는 자료는 필요한 링크를 확인하며, 작업을 완료했다고 추측하지 않는다. 실기 단계는 사용자 확인을 기다린다.

4·5단계는 각각 Claude 의뢰 여부를 먼저 확인한다. Claude에는 사용자가 프롬프트를 전달하고 GPT/Codex가 반환 결과를 검토해 실제 작업을 수행한다. 모든 단계 종료 시 결과와 다음 작업 프리뷰(예상 작업시간, 추천 모델·추론 강도, 필요한 준비·사용자 답변)를 안내한다.

모든 신규·진행 중 한글화 프로젝트는 3단계에서 전용 에뮬을 설정한다. 기본 롬 탐색·게임 목록 경로는 해당 게임의 `04_테스트 파일`로 지정하고, 공통 키보드 배치를 적용한다. 설정 분리·실제 저장 경로·재실행 후 유지 여부를 확인한 뒤 롬 분석으로 넘어간다. 이미 적용된 경우는 기록과 실제 설정을 확인하고 키보드 배치를 다시 입력하도록 요구하지 않는다. [공통 키 배치와 확인 절차](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/EMULATOR-TEST-SETUP.md)를 읽는다.

10·13·14단계는 각각 시작 전에 **“이 단계의 분석·분류 담당은 누구로 할까요? 실제 작업을 맡을 워커는 누구로 할까요?”**라고 묻고 사용자 배분을 기다린다. Claude·GPT·Codex 중 누구도 고정 담당으로 두지 않는다. 이미 해당 단계의 역할을 명시했다면 그 선택을 따르고 미정 역할만 확인한다. 선택은 다음 단계로 자동 승계하지 않는다. 역할별 작업 범위와 결과 전달 방식을 기록하고, 외부 담당을 선택하면 의뢰 프롬프트와 필요한 자료를 준비한다. Claude 의뢰는 사용자가 직접 전달하고 결과를 가져오며, 실제 작업은 사용자가 지정한 워커가 수행한다. 모델·워커를 임의로 호출하거나 바꾸지 않는다.
