# <게임명> 작업 시작하기

프로젝트와 총괄 담당자는 사용자가 지정한다. 지정된 총괄은 **프로젝트 시작 즉시, 1단계 문서·폴더 준비에 앞서 같은 프로젝트 안에 주 워커·이미지 식질 워커·동영상 자막 워커의 독립된 Codex 대화 3개를 생성·준비**한다. 이미 연결된 역할은 재사용하고 없는 역할만 생성한다. 총괄·프로젝트를 임의로 만들거나 바꾸지 않고, 워커 생성 허락을 다시 묻거나 롬 분석 단계까지 미루지 않는다. 서브에이전트로 대체하지 않는다.

Codex와 GPT 모두 먼저 [공통 작업순서](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/CODEX-LOCALIZATION-BOOTSTRAP.md)와 [공통 지시문](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/templates/PROJECT-INSTRUCTIONS.md)을 읽는다. 현재 사용자 지시와 승인 규칙을 우선한다.

게임명이 정해지면 기본 폴더부터 만든다. 사용자에게 `00_원본`과 `09_전용_에뮬` 경로를 안내한다. 원본 롬은 사용자가 준비한다. 에뮬은 담당자가 공용 보관함에서 플랫폼에 맞는 것을 프로젝트의 `09_전용_에뮬`로 복사해 준비한다. 원본이 없다고 경로를 반복해서 묻거나 폴더 생성을 미루지 않는다.

기본 폴더는 `00_` → `01_` → `02_` → `03_` → `04_` → `05_` → `06_` → `07_` → `08_` → `09_` → `10_` → `11_` → `12_` 번호 순서대로 하나씩 생성한다.

처음 준비할 때 `03_검수_자료`을 만든 직후 `00_한글화 패치 자료` → `01_일본어 추출` → `02_원문·2차 준비` → `03_검수완료` 하위 폴더도 순서대로 만든다. `00_한글화 패치 자료`는 사용자가 제공한 한글화 패치·참고 자료 보관용이며, 자료가 없으면 빈 폴더로 준비한다. 신규 프로젝트 생성 기준에 적용하고 기존 프로젝트의 자료·폴더는 임의로 이동하거나 이름을 바꾸지 않는다. 5번의 일본어·영어·혼용 원문 전체 추출과 원본 보존, 카테고리(캐릭터·스킬·아이템·시스템·대사, 이름/설명/메뉴/튜토리얼 서브타입)·루트/분기·장면 분류·스토리 순서 정렬 파생 사본은 `01_일본어 추출`, 6번의 5단계 메타데이터 재사용·`row_key` 부여/보존, 전체 원장·카테고리별 500행 CSV는 `02_원문·2차 준비`에 저장한다. 분할 CSV는 그 아래 카테고리 폴더별로 보관한다.

`02_원문·2차 준비` 아래에도 `01_캐릭터` → `02_스킬` → `03_아이템` → `04_시스템` → `05_대사`를 처음부터 순서대로 만든다. 각 카테고리의 최대 500행 파일을 해당 폴더에 넣고 `category`와 `row_key`는 유지한다.

`03_검수완료`는 처음에는 빈 폴더로 만든다. 폴더가 있다는 이유로 검수 완료로 표시하지 않는다. 4차 전체 검수 후 Drive `06_검수완료`의 최종 CSV·병합 원장·확정 용어/인물/관계·사용한 지시문을 `03_검수_자료/03_검수완료`에 보관한다. 가져온 자료의 Drive 폴더 구분과 카테고리·파일명은 유지하고 기존 입력·성공 자료를 덮어쓰지 않는다.


테스트 롬·ISO/CSO·사용자 확인용 빌드는 모두 해당 게임의 `04_테스트 파일`에 저장한다. 최소 한글 출력, 전체 원장 적용·문제 발생 시 초반 500개 진단, 이미지·동영상 자막, 통합 테스트에도 같은 저장 위치를 사용한다.

테스트 ROM·ISO/CSO를 만들 때는 ISO만 제공하지 않고 **해당 빌드를 바로 부팅하는 실행용 `.cmd`를 같은 테스트 폴더에 함께 만든다.** `09_전용_에뮬`의 실제 실행 파일과 해당 테스트 ROM을 연결하고, 더블클릭하면 에뮬레이터 실행과 게임 부팅까지 이어지도록 게임·에뮬별로 확인한 실행 인자를 사용한다. 공백·한글 경로를 인용하고 파일 존재를 확인하며, 어느 빌드를 실행하는지 파일명·안내에 명시한다. 에뮬만 열리고 게임 선택을 다시 요구하는 실행기는 완료로 보지 않는다. `.cmd` 작성·정적 확인과 실제 부팅 확인은 구분해 기록한다.

폴더 준비 완료를 먼저 보고하고 아래 실제 경로를 안내한다. 원본은 사용자가 준비하고 에뮬은 담당자가 공용 보관함에서 복사한다.

- 원본 등록 위치: `<사용자가 선택한 작업 경로>/<게임명>/00_원본`
- 한글화 패치·참고 자료 보관 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/00_한글화 패치 자료`
- 전체 원문 추출·원본 보존·카테고리/루트 정렬 파생 사본 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/01_일본어 추출`
- 6번 전체 원장·카테고리별 500행 CSV 준비 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/02_원문·2차 준비`
- 4차 최종 자료 보관 위치: `<사용자가 선택한 작업 경로>/<게임명>/03_검수_자료/03_검수완료`
- 테스트 파일 저장 위치: `<사용자가 선택한 작업 경로>/<게임명>/04_테스트 파일`
- 공용 보관함에서 복사할 전용 에뮬 위치: `<사용자가 선택한 작업 경로>/<게임명>/09_전용_에뮬`
- 진행상태: <현재 단계와 증거를 기록한 파일 링크>
- 게임정보·검증된 출력 규격: <실제 파일 링크>
- 전체 원장: <실제 파일 링크>
- 전용 에뮬: `09_전용_에뮬` — <포터블 복사·설정 분리 상태와 확인 기록>
- 검수 작업공간: <권한에 맞는 링크; 비공개 주소는 공개 저장소에서 제외>
- 기존 성공 자료·사용자 확정값: <실제 파일 링크>

진행상태를 읽고 현재 단계에서 이어서 작업한다. 접근할 수 없는 자료는 필요한 링크를 확인하며, 작업을 완료했다고 추측하지 않는다. 실기 단계는 사용자 확인을 기다린다.

3·4단계는 각각 Claude 의뢰 여부를 먼저 확인한다. 승인된 연결이 있으면 담당자가 Claude와 직접 의뢰·회신하고 실제 작업을 배차한다. 모든 단계 종료 시 결과와 다음 작업 프리뷰(예상 작업시간, 추천 모델·추론 강도, 필요한 준비·사용자 답변)를 안내한다.

4단계 빌드는 임시 폰트가 아니라 사용자 지정 폰트 마스터 `D:/Codex/한글화 프로젝트/# Font 모음/MaruBuri-SemiBold-HD-PPSSPP`를 실제 소스로 적용한다. 빌드 전에 마스터의 `README-ko.md`와 `다른-게임-적용-설명서.md`를 읽고 `font/MaruBuri-SemiBold.otf`와 누락 한글용 NotoSerifKR 대체 매니페스트를 쓴다. `full-hangul-master`의 13px/52px 프로필은 참고하되 다른 게임의 13px/3줄·PPSSPP 텍스처 해시를 강제하지 않고, 대상 게임에 맞춰 셀·크기·베이스라인·인코딩·엔진을 조정한다. PPSSPP HD 텍스처는 실제 대상 게임 덤프 해시가 있을 때만, 다른 엔진은 변환 글리프 자산으로 만든다. 마스터 원본은 읽기 전용이며 소스 해시와 최종 폰트 프로필을 테스트 빌드에 기록한다. 사용할 수 없거나 호환되지 않으면 임의 대체 없이 정확한 기술적 차단 사유를 보고한다. 사용자 지정 폰트는 첫 테스트 전 3종 후보 비교보다 우선하고, 이후 변경은 영향받은 문장·조건만 재시험한다.

첫 20문장 시험은 [조기 텍스트 런타임 게이트](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/EARLY-TEXT-RUNTIME-GATE.md)를 먼저 읽고 설계한다. 문장 1은 짧은 한글, 2~20은 다양한 조건 행렬이며 표 번호별 `row_key`/원문, 실제 주입 텍스트, 변경 조건, 기대 출력, 다음 전환을 기록하고 적용 가능한 축(가로 경계·세로/최대 줄 수·자동/명시 줄바꿈·`[n]` 조작 각각·반각/전각·한글/라틴/숫자/공백/문장부호·긴 한글/변수·인코딩/버퍼/제어)에 문장 ID를 배정한다. N/A는 구체적 근거·이유로 표시하고, 첫 20문장에 없는 조작을 강제로 추가하거나 잘못된 과대 데이터·보편적 무결점 보증으로 표현하지 않는다. 인계 전에 정적 빌드·원문→최종 매핑, 글리프 커버리지, 보호 필드·예산, 실제 폰트·주입 여부를 확인하고 테스트 빌드 1개·실행 `.cmd` 1개·1~20 대응표만 넘긴다. 주입 없는 체크리스트는 인계로 보지 않으며, 적용 가능한 미완료 항목이 있으면 완료·준비로 표시하지 않는다. 사용자는 첫 문장부터 20번째 다음 전환까지 한 번 순차 플레이하며 확인 전에는 보류로 둔다. 도달 불가 전환은 강제로 건너뛰거나 런타임 PASS를 만들지 말고 한계로 기록하고, 실패 시 해당 문장·조건만 재시험하며 기존 확인 조건은 재사용한다. 별도 검사 프로그램은 만들지 않는다.

모든 신규·진행 중 한글화 프로젝트는 2단계에서 전용 에뮬을 설정한다. 기본 롬 탐색·게임 목록 경로는 해당 게임의 `04_테스트 파일`로 지정하고, 공통 키보드 배치와 기본 패드 매핑을 모두 적용한다. 키보드 설정을 작성할 때 에뮬의 기존 패드 매핑을 삭제하거나 덮어쓰지 않는다. 패드는 버튼 위치·방향키·스틱·숄더·트리거·Start/Select를 지원 기종에 맞춰 연결하고, 미연결이면 기본 매핑을 보존·준비한 뒤 패드 입력 확인만 대기로 남긴다. 설정 분리·실제 저장 경로·재실행 후 유지 여부를 확인한 뒤 롬 분석으로 넘어간다. 이미 적용된 경우는 기록과 실제 설정을 확인하고 키보드·패드 매핑을 다시 입력하도록 요구하지 않는다. [공통 키 배치와 확인 절차](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/EMULATOR-TEST-SETUP.md)를 읽는다.

10·11단계는 각각 시작 전에 **“이 단계의 분석·분류 담당은 누구로 할까요? 실제 작업을 맡을 워커는 누구로 할까요?”**라고 묻고 사용자 배분을 기다린다. Claude·GPT·Codex 중 누구도 고정 담당으로 두지 않는다. 이미 해당 단계의 역할을 명시했다면 그 선택을 따르고 미정 역할만 확인한다. 선택은 다음 단계로 자동 승계하지 않는다. 역할별 작업 범위와 결과 전달 방식을 기록하고, 외부 담당을 선택하면 의뢰 프롬프트와 필요한 자료를 준비한다. 승인된 연결이 있으면 담당자가 직접 의뢰·회수하고 실제 작업은 사용자가 지정한 워커가 수행한다. 모델·워커를 임의로 호출하거나 바꾸지 않는다.


## 사용자 지정 베이스 보존

처음 폴더를 준비할 때 **`04_테스트 파일/00_베이스 파일`만 빈 폴더로 생성**한다. 사용자가 베이스로 명시한 파일만 이곳에 사본으로 보존하고, 지정 순서대로 `01_`, `02_` 등의 번호와 실제 특징을 붙여 구분한다. `01_띄어쓰기 수정`, `02_스피커 적용`은 이름 예시일 뿐이며 처음부터 해당 파일이나 하위 폴더를 만들지 않는다. 이전 베이스와 원본은 덮어쓰거나 이동하지 않는다. 현재 적용할 베이스의 정확한 경로·원래 파일명·지정 순번·특징·사용자 지정 근거를 진행상태에 기록한다. 임의의 최신 테스트 빌드를 사용자 지정 베이스로 간주하지 않는다.

## 1단계에서 Dollars Archive 게임 대문도 등록한다

**사용자 확정 공통 지시: 신규 한글화 프로젝트 준비·착수 요청에는 1단계의 Dollars Archive 게임 대문 등록·게시가 포함된다.** 이는 이미 요청된 필수 작업이므로 ‘공개 사이트 변경’, ‘외부 전송’, ‘별도 게시 승인 필요’라는 이유만으로 재승인을 요구하거나 생략하지 않는다. Codex·Claude 어느 쪽에서 직접 시작해도 같은 기준을 적용한다. 이 허용 범위는 확인된 게임 정보·표지·작업 중 상태·공개 연결 링크를 담은 라이브러리 카드와 필요한 최소 공개 기록용 저장소/README 준비·등록에 한정한다. 게임 원본·추출물·패치 파일·Release 배포, 개인정보·비공개 자료 공개나 저장소 공개 범위 변경까지 자동 허용하지 않는다.

문서·기본 폴더 준비와 함께 **[Dollars Archive 게임 라이브러리](https://dollars-archive.github.io/Dollars-Archive/)**에도 해당 게임을 등록한다. 프로젝트 총괄이 같은 게임·기종·판본의 기존 등록을 먼저 확인하고, 있으면 기존 항목을 재사용·갱신하며 없으면 새 게임 대문을 만든다. 이 등록을 후반 배포 단계까지 미루지 않는다.

게임명·원제·기종·판본과 확인된 게임 정보, 프로젝트 저장소·발굴 아카이브 링크 등 실제 확보한 자료를 연결한다. 한글화 상태는 실제 진행에 맞추고, 신규 착수 시 메뉴·UI·대사·이미지·영상 자막·공략집·HD 팩의 완료 체크는 실제 완료 근거나 사용자 확인이 있을 때만 표시한다. 기존 확정 제목·완료 상태·자료는 보존하고 모르는 정보를 추측해 채우지 않는다. 대문 등록을 패치 파일·Release 배포로 해석하지 않는다.

**1단계 완료 조건과 보고:** 기본 폴더·운영 문서 준비만으로 ‘1단계 완료’라고 보고하지 않는다. 총괄이 기존 등록 확인 → 없으면 등록에 필요한 공개 기록용 저장소/README와 허브 메타데이터 준비 → 등록·갱신 게시 → 자동 수집·배포 결과 및 실제 사이트 카드 확인까지 마친다. 기존 카드가 있으면 중복 생성하지 않고 같은 기종·판본과 현재 상태를 확인한다.

- `진행상태.md`와 완료 보고에 **클릭 가능한 게임 대문 URL, 신규/기존 등록 구분, 실제 사이트 반영 확인 결과**를 반드시 남긴다.
- 등록 누락을 발견하면 먼저 같은 승인 범위에서 등록을 마치고 보고한다. ‘필요하면 등록하겠다’, ‘등록은 별도 승인을 기다린다’, ‘나중에 대문에 추가한다’로 끝내지 않는다.
- 실제 권한·인증·게시 도구 오류로 불가능할 때만 해당 항목을 보류한다. 실행한 시도·오류와 준비한 등록 내용·필요 조치를 기록하고 **1단계 미완료/등록 보류**로 보고한다. 단순히 공개 작업이라는 이유는 차단 사유가 아니다. 사용자에게 인증값을 채팅으로 보내도록 요구하지 않는다.

등록·갱신 후 사이트 반영을 확인하고 대문 URL·등록 결과·미확인 사항을 `진행상태.md`에 남긴다. 저장소 쓰기 권한이나 게시 도구가 없으면 준비한 등록 내용과 정확한 막힌 지점을 기록하며 완료로 표시하지 않는다. 다른 사용자는 본인이 지정한 라이브러리를 사용한다.
