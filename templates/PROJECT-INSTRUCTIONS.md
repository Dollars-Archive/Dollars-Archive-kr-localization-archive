# Codex·GPT 공통 작업 지시문

이 게임의 한글패치 작업은 [최신 16단계 부트스트랩](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/CODEX-LOCALIZATION-BOOTSTRAP.md)을 따른다. 현재 사용자 지시와 승인 규칙이 우선한다.

1. 시작하기.md에 있는 이 게임의 자료 링크와 진행상태.md를 실제로 읽는다. 지난 채팅의 기억으로 현재 상태를 추측하지 않는다.
2. 현재 단계의 선행 조건을 확인한다. 파일과 확인 근거가 있는 완료 단계는 반복하지 않는다. 미확인 단계는 완료로 처리하지 않는다.
3. 이번 단계에서 필요한 작업만 수행한다. 사용자 승인 규칙이 있으면 그 승인 범위 안에서 진행한다.
4. 결과를 해당 게임의 정해진 위치에 저장하고 다시 열어 확인한다. 진행상태에 단계·파일 링크·검증 결과·사용자 확인·다음 할 일을 기록한다.
5. 실기 확인 단계는 사용자 확인 전까지 대기로 둔다. 테스트 파일, 진입 경로, 조작, 볼 문구·화면과 기대 결과를 안내한다.
6. GPT에 로컬 파일·빌드·실기 도구가 없으면 필요한 작업과 자료를 기록해 Codex/사용자에게 넘긴다. 없는 도구로 실행하거나 저장했다고 말하지 않는다. 이 때문에 앞뒤 순서를 건너뛰지 않는다.
7. Drive 검수는 각 차수의 지시문대로 파일당 최대 500행 전체를 처리한다. 같은 파일명으로 다음 폴더에 저장하고 진행표를 갱신한다. 차수 전체가 끝나면 기준 자료를 정리한 뒤 다음 차수로 간다.
8. 지시문이나 자료에 접근할 수 없으면 필요한 링크와 현재 막힌 지점을 알린다. 읽지 못한 문서를 읽었다고 하거나 완료로 표시하지 않는다.

9. 4·5단계는 각각 시작 전에 분석·설계 담당을 확인한다. 이미 해당 단계의 담당을 명시한 경우는 다시 묻지 않는다. Claude 선택과 직접 교환이 승인된 경우 프로젝트 담당자가 브리지로 의뢰·질문·결과 회수를 직접 처리한다. 결과를 검토한 뒤 주 워커에게 실제 파일 수정·빌드·샘플 제작을 배차한다. 단계 승인과 담당 선택 전에는 해당 작업을 시작하지 않는다.
10. 모든 단계가 끝날 때마다 완료 보고를 한다. 이번 결과를 짧게 적고, **다음 작업 프리뷰: 단계 번호·이름, 예상 작업시간, 추천 모델·추론 강도와 간단한 이유, 필요한 준비·사용자 답변**을 함께 안내한다. 예상시간은 자료 규모와 남은 확인에 근거하고 미확정이면 조건을 밝힌다. “준비되면 말씀해 주세요” 또는 담당 선택·실기 확인 요청으로 끝낸다. 결과만 나열하고 끝내지 않는다. 추천은 모델 자동 변경·호출 허가가 아니다. 승인이나 담당 선택이 필요한 다음 단계는 사용자 답변을 받은 뒤 시작한다. 전체 16단계가 끝났으면 전체 완료를 보고하고 예정되지 않은 후속 작업을 만들지 않는다.

11. 모든 신규·진행 중 한글화 프로젝트는 3번과 4번 사이의 3-1단계에서 전용 에뮬을 설정한다. 기본 롬 탐색·게임 목록 경로는 해당 게임의 `04_테스트 파일`로 지정하고, 공통 키보드 배치를 적용한다. 설정 분리·실제 저장 경로·재실행 후 유지 여부를 확인한 뒤 롬 분석으로 넘어간다. 이미 적용된 경우는 기록과 실제 설정을 확인하고 키보드 배치를 다시 입력하도록 요구하지 않는다. [공통 키 배치와 확인 절차](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/EMULATOR-TEST-SETUP.md)를 읽고 적용한다.

12. 12·13·14단계는 각각 시작 전에 **“이 단계의 분석·분류 담당은 누구로 할까요? 실제 작업을 맡을 워커는 누구로 할까요?”**라고 묻고 사용자 배분을 기다린다. Claude·GPT·Codex 중 누구도 고정 담당으로 두지 않는다. 이미 해당 단계의 역할을 명시했다면 그 선택을 따르고 미정 역할만 확인한다. 분석·분류 담당 선택은 다음 단계로 자동 승계하지 않는다. 등록된 프로젝트 담당자와 실무자 대화는 계속 재사용한다. 역할별 작업 범위와 결과 전달 방식을 기록하고, 외부 담당을 선택하면 의뢰 프롬프트와 필요한 자료를 준비한다. Claude 의뢰는 승인된 직접 연결로 프로젝트 담당자가 전달·회수한다. 일반 작업은 주 워커, 이미지는 이미지 워커, 동영상은 동영상 워커에게 배차한다. 이미 지정된 실무자는 다시 묻지 않고 미정 역할만 확인한다. 사용자가 다른 배분을 정하면 이를 따르며 모델·워커를 임의로 바꾸지 않는다.

## 단계 완료 보고

결과 → 다음 작업과 예상시간·추천 모델/추론 → 필요한 준비·선택 순서로 짧게 보고한다. 준비 단계 종료 예시:

```text
폴더·문서 준비와 원본 등록, 기존 한글패치 조사 및 3-1단계 전용 에뮬 설정을 마쳤습니다.
다음 작업은 4단계 텍스트·폰트·인코딩 분석입니다.
예상 작업시간: <자료 규모에 따른 예상 범위>
추천 모델·추론 강도: <모델 / 강도> — <간단한 이유>
준비되면 Claude에게 분석을 맡길지, Codex가 직접 할지 알려주세요.
```

현재 상태에 따라 필요한 원본·포터블 복사나 실기 확인도 구체적으로 안내한다. 예시의 완료 항목은 실제로 확인한 경우에만 사용한다.

## 처음 세팅할 때

작업 경로·GitHub·Drive는 현재 사용자 환경을 사용한다. 작성자 개인 경로·저장소 연결은 본인 환경용으로 바꾸거나 생략한다. 검수 프로그램은 각자 게임에 맞춰 직접 제작한다.

게임명이 정해지면 기본 폴더부터 만든다. 사용자에게 `00_원본`과 `09_전용_에뮬` 경로를 안내한다. 원본·포터블 복사는 사용자가 한다. 원본이 없다고 경로를 반복해서 묻거나 폴더 생성을 미루지 않는다.

기본 폴더는 `00_` → `01_` → `02_` → `03_` → `04_` → `05_` → `06_` → `07_` → `08_` → `09_` → `10_` 번호 순서대로 하나씩 생성한다.

처음 준비할 때 `03_검수_자료`을 만든 직후 `00_일본어 추출` → `01_1차 검수 준비` 하위 폴더도 순서대로 만든다. 7번의 일본어·영어 전체 추출·백업은 `03_검수_자료/00_일본어 추출`, 8번의 원장·카테고리별 500행 CSV는 `03_검수_자료/01_1차 검수 준비`에 저장한다. 분할 CSV는 그 아래 카테고리 폴더별로 보관한다.

`01_1차 검수 준비` 아래에도 `01_캐릭터` → `02_스킬` → `03_아이템` → `04_시스템` → `05_대사`를 처음부터 순서대로 만든다. 각 카테고리의 최대 500행 파일을 해당 폴더에 넣고 `category`와 `row_key`는 유지한다.

테스트 롬·ISO/CSO·사용자 확인용 빌드는 모두 해당 게임의 `04_테스트 파일`에 저장한다. 최소 한글 출력, 초반 500개 대사, 이미지·동영상 자막, 통합 테스트에도 같은 저장 위치를 사용한다.

폴더와 시작 안내·진행상태 파일을 만든 뒤 실제 생성 경로를 확인하고 **“폴더 준비 완료”**를 먼저 보고한다. `00_원본`에는 원본 롬, `09_전용_에뮬`에는 포터블 에뮬을 넣도록 안내한다. 준비 보고 전에는 원본 탐색이나 한글패치 여부 조사를 시작하지 않는다. 파일 복사 전에는 원본 등록·전용 에뮬 세팅 대기로 기록하고, 복사 완료 후 등록 파일을 확인해 다음 작업을 진행한다.

- 이 문서를 프로젝트 시작하기.md에서 연결하고 AGENTS.md에도 연결한다.
- `09_전용_에뮬` 폴더를 준비한다. 사용자 포터블 복사 후 게임 테스트용 설정·세이브 경로를 분리하고 실제 저장 경로와 재실행 확인 결과를 진행상태에 기록한다. 도구가 없는 GPT는 설정을 완료했다고 하지 않고 Codex/사용자 확인 대기로 남긴다.
- 게임 저장소 README에는 공통 순서와 시작하기 링크를 연결한다. 비공개 Drive 주소는 공개 README에 넣지 않는다.
- Drive 작업공간에는 이 문서의 본문을 `공통작업지시문.md`, 최신 부트스트랩 본문을 `작업순서.md`로 복사한다. 공통 양식과 진행상태를 함께 올리고 시작하기.md에서 실제 파일 링크를 연결한다.
- 게임별 진행상태는 한 개만 원본으로 사용한다. Drive 준비 후에는 Drive 파일을 원본으로 정하고 로컬에서는 그 링크를 참조한다. 최신 공통 순서가 바뀌면 작업순서.md도 갱신한다.

새 GPT 대화에서도 게임 자료의 시작하기.md를 먼저 읽으면 같은 순서로 이어갈 수 있게 한다. 이 문서를 저장하는 것만으로 모든 새 GPT 대화에 자동 주입되지는 않으므로 게임의 시작 안내와 함께 연결한다.

## 프로젝트 담당자와 실무자

[프로젝트 담당자·실무자 연결 규칙](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/PROJECT-COORDINATION.md)을 읽는다. 사용자 지정 독립 대화 4개(프로젝트 담당자·주 워커·이미지 워커·동영상 워커)의 실제 ID를 `01_프로젝트_문서/작업배분.json`에 기록하고 재사용한다. 담당자가 승인된 단계 안에서 Claude와 직접 교환하고 해당 실무자에게 배차·회수·검토한다. 사용자에게 메시지 복사를 요구하지 않는다. 연결 설정만으로 다음 단계 작업 승인을 대신하지 않는다.
