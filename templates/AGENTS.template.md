## 프로젝트 구조

게임명이 정해지면 기본 폴더부터 만든다. 사용자에게 `00_원본`과 `09_전용_에뮬` 경로를 안내한다. 원본·포터블 복사는 사용자가 한다. 원본이 없다고 경로를 반복해서 묻거나 폴더 생성을 미루지 않는다.

기본 폴더는 `00_` → `01_` → `02_` → `03_` → `04_` → `05_` → `06_` → `07_` → `08_` → `09_` → `10_` → `11_` → `12_` → `13_` 번호 순서대로 하나씩 생성한다.

처음 준비할 때 `03_검수_자료`을 만든 직후 `00_일본어 추출` → `01_1차 검수 준비` → `02_3차 검수 완료` → `04_검수 프로그램` 하위 폴더도 순서대로 만든다. 7번의 일본어·영어 전체 추출·백업은 `03_검수_자료/00_일본어 추출`, 8번의 원장·카테고리별 500행 CSV는 `03_검수_자료/01_1차 검수 준비`에 저장한다. 분할 CSV는 그 아래 카테고리 폴더별로 보관한다.

`01_1차 검수 준비` 아래에도 `01_캐릭터` → `02_스킬` → `03_아이템` → `04_시스템` → `05_대사`를 처음부터 순서대로 만든다. 각 카테고리의 최대 500행 파일을 해당 폴더에 넣고 `category`와 `row_key`는 유지한다.

`02_3차 검수 완료`는 처음에는 빈 폴더로 만든다. 폴더가 있다는 이유로 검수 완료로 표시하지 않는다. 3차 전체 검수 후 Drive 최종 CSV·병합 원장·확정 용어/인물/관계·사용한 지시문을 `03_검수_자료/02_3차 검수 완료`에 보관한다. 가져온 자료의 Drive 폴더 구분과 카테고리·파일명은 유지하고 기존 입력·성공 자료를 덮어쓰지 않는다.

`04_검수 프로그램` 폴더도 처음부터 빈 폴더로 만든다. 실제 검수 프로그램의 소스·실행 파일·설정은 `03_검수_자료/04_검수 프로그램`에 보관하고, 프로그램은 `02_3차 검수 완료`의 최신 병합 원장을 불러오도록 연결한다. 폴더 생성만으로 프로그램 제작·검증 완료를 표시하지 않는다.

테스트 롬·ISO/CSO·사용자 확인용 빌드는 모두 해당 게임의 `04_테스트 파일`에 저장한다. 최소 한글 출력, 초반 500개 대사, 이미지·동영상 자막, 통합 테스트에도 같은 저장 위치를 사용한다.

테스트 ROM·ISO/CSO를 만들 때는 ISO만 제공하지 않고 **해당 빌드를 바로 부팅하는 실행용 `.cmd`를 같은 테스트 폴더에 함께 만든다.** `09_전용_에뮬`의 실제 실행 파일과 해당 테스트 ROM을 연결하고, 더블클릭하면 에뮬레이터 실행과 게임 부팅까지 이어지도록 게임·에뮬별로 확인한 실행 인자를 사용한다. 공백·한글 경로를 인용하고 파일 존재를 확인하며, 어느 빌드를 실행하는지 파일명·안내에 명시한다. 에뮬만 열리고 게임 선택을 다시 요구하는 실행기는 완료로 보지 않는다. `.cmd` 작성·정적 확인과 실제 부팅 확인은 구분해 기록한다.

폴더와 시작 안내·진행상태 파일을 만든 뒤 실제 생성 경로를 확인하고 **“폴더 준비 완료”**를 먼저 보고한다. `00_원본`에는 원본 롬, `09_전용_에뮬`에는 포터블 에뮬을 넣도록 안내한다. 준비 보고 전에는 원본 탐색를 시작하지 않는다. 파일 복사 전에는 원본 등록·전용 에뮬 세팅 대기로 기록하고, 복사 완료 후 등록 파일을 확인해 다음 작업을 진행한다.

```text
00_원본
01_프로젝트_문서
02_한글화_작업
03_검수_자료
  ├─ 00_일본어 추출
  ├─ 01_1차 검수 준비
  │  ├─ 01_캐릭터
  │  ├─ 02_스킬
  │  ├─ 03_아이템
  │  ├─ 04_시스템
  │  └─ 05_대사
  ├─ 02_3차 검수 완료
  └─ 04_검수 프로그램
04_테스트 파일
05_한글 패치 배포
06_한글 패치 완료
07_이미지 식질
08_동영상 자막
09_전용_에뮬
10_버그 리포트
11_공략집
12_HD Texture
13_자동검수 프로그램
```

원본과 다른 게임 프로젝트는 수정하지 않는다. 기존 폴더를 강제로 재배치하지 않는다. HD Pack은 사용자 요청이 있을 때만 제작한다.

## 전용 에뮬

모든 신규·진행 중 한글화 프로젝트는 3단계에서 전용 에뮬을 설정한다. 기본 롬 탐색·게임 목록 경로는 해당 게임의 `04_테스트 파일`로 지정하고, 공통 키보드 배치를 적용한다. 설정 분리·실제 저장 경로·재실행 후 유지 여부를 확인한 뒤 롬 분석으로 넘어간다. 이미 적용된 경우는 기록과 실제 설정을 확인하고 키보드 배치를 다시 입력하도록 요구하지 않는다. [공통 키 배치와 확인 절차](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/EMULATOR-TEST-SETUP.md)를 읽고 적용한다.

`09_전용_에뮬`은 이 게임 테스트용이다. 사용자가 포터블을 복사한 뒤 설정·메모리카드·세이브·게임별 설정을 프로젝트 안에 분리한다. PCSX2 등의 실제 저장 경로와 재실행 후 설정 유지를 확인한다. 공용 문서 폴더의 설정·기존 세이브는 변경하지 않는다. 복사 전에는 세팅 대기이며, 저장 경로를 확인하기 전에는 분리 완료로 표시하지 않는다.

## 이어서 작업할 때

10·13·14단계는 각각 시작 전에 **“이 단계의 분석·분류 담당은 누구로 할까요? 실제 작업을 맡을 워커는 누구로 할까요?”**라고 묻고 사용자 배분을 기다린다. Claude·GPT·Codex 중 누구도 고정 담당으로 두지 않는다. 이미 해당 단계의 역할을 명시했다면 그 선택을 따르고 미정 역할만 확인한다. 분석·분류 담당 선택은 다음 단계로 자동 승계하지 않는다. 등록된 프로젝트 담당자와 실무자 대화는 계속 재사용한다. 역할별 작업 범위와 결과 전달 방식을 기록하고, 외부 담당을 선택하면 의뢰 프롬프트와 필요한 자료를 준비한다. Claude 의뢰는 승인된 직접 연결로 프로젝트 담당자가 전달·회수한다. 일반 작업은 주 워커, 이미지는 이미지 워커, 동영상은 동영상 워커에게 배차한다. 이미 지정된 실무자는 다시 묻지 않고 미정 역할만 확인한다. 사용자가 다른 배분을 정하면 이를 따르며 모델·워커를 임의로 바꾸지 않는다.

4·5단계는 각각 시작 전에 분석·설계 담당을 확인한다. 이미 해당 단계의 담당을 명시한 경우는 다시 묻지 않는다. Claude 선택과 직접 교환이 승인된 경우 프로젝트 담당자가 브리지로 의뢰·질문·결과 회수를 직접 처리한다. 결과를 검토한 뒤 주 워커에게 실제 파일 수정·빌드·샘플 제작을 배차한다. 단계 승인과 담당 선택 전에는 해당 작업을 시작하지 않는다.

모든 단계가 끝날 때마다 완료 보고를 한다. 이번 결과를 짧게 적고, **다음 작업 프리뷰: 단계 번호·이름, 예상 작업시간, 추천 모델·추론 강도와 간단한 이유, 필요한 준비·사용자 답변**을 함께 안내한다. 예상시간은 자료 규모와 남은 확인에 근거하고 미확정이면 조건을 밝힌다. “준비되면 말씀해 주세요” 또는 담당 선택·실기 확인 요청으로 끝낸다. 결과만 나열하고 끝내지 않는다. 추천은 모델 자동 변경·호출 허가가 아니다. 승인이나 담당 선택이 필요한 다음 단계는 사용자 답변을 받은 뒤 시작한다. 전체 16단계가 끝났으면 전체 완료를 보고하고 예정되지 않은 후속 작업을 만들지 않는다.

진행상태를 읽고 현재 단계의 입력·완료 조건을 확인한다. 결과 파일과 검증 근거를 기록한다. 실기 확인이 필요한 단계는 사용자 확인 전까지 완료로 표시하지 않는다. 실제 빌드·저장·모델 호출 없이 수행했다고 보고하지 않는다.

Drive 검수는 [공통 양식](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/templates/drive-review/README.md)을 사용한다. 1·2·3차 모두 최대 500개 데이터 행이며, 기존 프로그램의 CSV 열을 보존한다. 1차 번역 → 2차 화자·관계·용어 확정 → 3차 출력 규격·말투 반영 순서를 지킨다.

검수 프로그램은 최신 원장을 자동으로 불러오고 대사를 실제 스토리 순서로 표시한다. 검수 프로그램은 각자 게임에 맞춰 직접 제작한다. 실기 확인 순서는 부트스트랩 10~16번을 따른다.

모델과 작업 배분은 현재 사용자 지시를 따른다. Web GPT·Oracle·외부 모델과 보조 에이전트는 현재 작업에서 명시적으로 요청받았을 때만 사용한다. 문서를 읽는 것만으로 모델 호출을 허가받은 것으로 보지 않는다.

공개 작업일지는 필요할 때 [기존 표준](https://github.com/Dollars-Archive/Dollars-Archive-kr-localization-archive/blob/main/workflow/PUBLIC-WORKLOG-STANDARD.md)을 적용한다.

## Public Patch README Form

아래 Dollars-Archive 허브·공략집 연결은 작성자 운영용이다. 다른 사용자는 본인 저장소용으로 수정하거나 생략하고 작성자 저장소에 게시하지 않는다.
### 새 패치 저장소의 숨김 공략집 지침

공개 README에 `직접 만든 공략집 등록 안내` 또는 REGISTER-GUIDE.md 등록 절차 링크를 보이는 문구·버튼으로 생성하거나 복원하지 않는다. 등록 지침 URL과 patch_repo는 `DOLLARS-WALKTHROUGH-REGISTRATION` HTML 주석 안에만 보존한다. 실제 공략집 열기·다운로드 링크와 모음집의 공략집 체크는 유지한다.

신규 공개 패치 저장소 생성은 README의 공략집 등록 지침 연결까지 포함합니다. `templates/README.template.md`의 HTML 주석 안 지침만 보존하고 `REPOSITORY_NAME`을 실제 저장소 이름으로 바꿉니다. `templates/ensure_guide_registration.py`를 `.github/scripts/ensure_guide_registration.py`, `templates/guide-registration.yml`을 `.github/workflows/guide-registration.yml`로 함께 복사합니다. 첫 커밋 전에 `python .github/scripts/ensure_guide_registration.py --repo Dollars-Archive/실제저장소이름`을 실행합니다.

워크플로는 기본 브랜치 푸시와 수동 실행 때 누락된 연결만 자동으로 추가합니다. 숨김 지침은 보존하며 보이는 등록 안내가 남아 있으면 제거합니다. 올바른 문서는 다시 변경하지 않습니다. 신규 저장소 생성 완료 전에 지침 주소·patch_repo·워크플로 실행 성공을 확인하며, 사용자가 따로 지침을 첨부하도록 요구하지 않습니다. 공략 등록 요청은 https://github.com/Dollars-Archive/Game-Walkthrough-Archive/blob/main/REGISTER-GUIDE.md 를 직접 읽고 처리합니다. 별도 PAT 없이 자기 저장소의 GITHUB_TOKEN을 사용합니다. 세부 절차는 `workflow/PATCH-README-STANDARD.md`에 있습니다.


공개 패치 저장소의 대문을 만들 때 canonical bootstrap의 `templates/README.template.md`를 사용합니다. 게임 정보 표에는 개발사·장르·발매일·플레이타임을 포함합니다. `타이틀 한글화 / 메뉴·UI / 대사 / 이미지 번역 / 동영상 자막`의 다섯 제목과 각 항목의 숨김 주석 `kr-patch:state:`를 유지합니다. 공개 상태 문구는 추가하거나 복원하지 않습니다. 완료·일부·미작업·해당 없음으로 명시하고 근거 없는 완료 표시를 하지 않습니다. ## 프로젝트 담당자와 실무자
